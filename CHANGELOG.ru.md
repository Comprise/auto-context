# История изменений

English version: [CHANGELOG.md](CHANGELOG.md). Заметки релиза тега — раздел `## vX.Y.Z` файла CHANGELOG.md.

## v1.1.0

### Breaking

- **Обновляйте плагин на всех машинах команды одновременно.** Плагин v1.0.0 не понимает хэши `v2:`
  и при собственном auto-ack переписывает их обратно в `sha256:`. При смешанных версиях
  frontmatter будет туда-обратно меняться в коммитах.
- **Схема хэша v2.** `source_hash` теперь `v2:sha256:<hex>` и считается по файлам юнита в том виде,
  как их видит git (только записи индекса; неотслеживаемые файлы не учитываются; в режиме обхода —
  все найденные). `_root` хэширует юниты в том же индексном виде. Доки со старым хэшем `sha256:`
  показываются как `ok (old hash scheme)`, пока совпадают со старыми правилами;
  `auto-context ack --upgrade` переводит их на v2.
- **Известные разовые издержки обновления.** Юнит с файлом больше 32 MiB и `_root` (если каталог с
  пробелом в имени раньше был юнитом) один раз покажутся `stale`; после проверки доков выполните
  `auto-context ack <unit>` (или `ack --upgrade`).
- **`units.SafeName` строже:** пробел и ведущий `-` в любом сегменте пути запрещены. Такие каталоги
  больше не юниты, их доки становятся сиротами (`status` сообщает об этом).
- **Коды выхода:** 0 — успех, 1 — только `status --exit-code` при stale/missing, 2 — неверное
  использование, 3 — ошибка. Сбои `ack`, `units`, `changes` (проект не открыть, битый конфиг, отказ
  ack) теперь завершаются кодом 3, а не 1.
- **`--json`** для `status` и `units` (`format_version: 1`); сочетается с `--stale` и `--exit-code`.
- **Пределы:** не более 800 000 файлов в репозитории; файлы больше 32 MiB хэшируются выборкой
  (размер, первый и последний 1 MiB).
- **Кэш хэшей теперь `.auto-context/cache.v5.bin`** (бинарный). Старые файлы кэша игнорируются и
  могут быть удалены; `auto-context version -v` показывает `cache 5`.
- **Frontmatter:** неизвестные ключи теперь сохраняются при записи. Первый `ack` может переформатировать
  вложенные или свёрнутые значения неизвестных ключей.
- Проекты, созданные в v1, могут закрепить четыре ключа по умолчанию (`code_extensions`,
  `module_markers`, `exclude`, `min_files`) в `.auto-context/config.yaml`, чтобы будущие изменения
  умолчаний не меняли хэши (навык `init` теперь их записывает).
- Модуль YAML — `go.yaml.in/yaml/v3` (вместо `gopkg.in/yaml.v3`).

### Fixed

- Windows: снятие устаревшей блокировки больше не удаляет свежую, занявшую её место, а док или
  служебный файл, открытый другим процессом, заменяется после короткого повтора, а не с ошибкой.
- git больше не запускает программы из `.git/config` репозитория (транспорты ленивой догрузки,
  `gpg.program`, другие транспорты); по таймауту убивается вся группа процессов git; чужое дерево
  (`core.worktree`, `.git`-файл на другой репозиторий, bare) отвергается, связанные worktree и
  сабмодули по-прежнему работают через git.
- Текст репозитория не попадает в контекст Claude и в терминал, кроме очищенных имён юнитов, чисел,
  фиксированных категорий и вывода `changes`.
- Шим игнорирует пустые и относительные элементы `PATH` для своих утилит, бинарю отдаёт исходный `PATH`.
- Убран квадратичный разбор секции корневого индекса; блокировка ротации лога надёжнее (устаревшая блокировка удаляется, только если это тот же файл; flock через `SyscallConn`).
- Изменение набора юнитов внутри хода, шаги SessionStart, `--exclude`, дешёвый индексный вид и
  `changes` в сервисном слое, разбор входа хуков и ряд мелких дефектов полного ревью 2026-10-23.
- Хук, у которого кончилось время, останавливает git, обнаружение файлов и хэширование и отвечает тем, что успел (юниты без хэша или уведомление об исходе времени), а не убивается.
- Параллельные сессии в одном дереве не теряют хэши друг друга в кэше.
- Связанные worktree, созданные с относительными путями (`worktree.useRelativePaths`, git 2.48+),
  работают через git, а не через обход дерева.
- На Linux git завершается вместе с хуком, который агент убил по таймауту, а не остаётся работать.
- `ack` сохраняет комментарии неизвестных ключей frontmatter в файлах с концами строк CRLF.
- `/auto-context:sync` сообщает и о доках, подтверждённых по старой схеме хэша, и предлагает `auto-context ack --upgrade`.

### Added

- `auto-context ack --upgrade`, `auto-context version -v` (коммит, версия Go, ОС/архитектура).
- `SECURITY.md`, `docs/RELEASING.md` (hotfix, yank, откат, закрепление версии), шаблоны issue.

## v1.0.0

Первый стабильный релиз.

### Breaking

- В frontmatter новый ключ `commit`; блок без `unit` или `source_hash` больше не считается «нашим»;
  BOM сохраняется. Старый плагин (v0.0.x) стирает `commit` при `ack`, и `changes` откатывается к
  поиску по дате: держите в команде одну версию плагина.
- `.auto-context/cache.json` версии 2 стал версией 3 (старые кэши молча отбрасываются).
- Конфиг: `index_file` строже — повторный ключ или не строка ломает весь конфиг.
