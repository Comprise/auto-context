# internal/session
Файлы сессии одного хода: снимок отслеживаемых файлов и журнал Stop.

## Назначение
PromptSubmit сохраняет снимок (mtime/size отслеживаемых файлов), Stop сравнивает с ним текущее состояние и ведёт журнал хода: какой код менялся, какие доки трогались, о чём уже напомнили. Файлы — `.auto-context/state/<id>.snapshot` и `<id>.json`, где `<id>` — `SanitizeID`.

## Публичный API / точки входа
- `Snapshot` — срез `Entry{Path, Stat}` (`filestat.Stat`), отсортированный по пути, каждый путь один раз; `Get`/`Has` — двоичный поиск. Срез вместо карты: на больших деревьях вторая карта на все файлы — заметная доля памяти хука.
- `FromTree(tracked, stats)` — из отсортированного `Tree.Tracked()` и карты `Tree.StatsView()` (только читается, не копируется); файл без stat пропускается. `FromMap(m)` — из карты (сортирует).
- `Diff(before, after)` — изменённые, удалённые, добавленные пути, отсортированы: слияние двух отсортированных снимков за один проход. `Get` и `Diff` ждут нормализованный снимок (отсортирован, пути без повторов) — таким его оставляют все конструкторы; `Diff` проверяет это за один проход и нормализует копию собранного вручную среза (`TestDiffUnsortedInput`).
- `SnapshotTime` — mtime файла снимка в ns, то есть начало хода; нет файла — ошибка с `os.ErrNotExist`.
- `LoadSnapshot` / `Save`; снимок без заголовка или с битой записью — ошибка с путём файла.
- `Journal`: `LoadJournal`, `Save`, `AddCode`/`AddDocs`/`Notify`, `Pause`/`Paused` (конфиг ломался в этой сессии; снимок до паузы, если он есть, сохраняется), `MarkConfigNotified`/`ConfigNotified` (Stop уже сказал об этом), `Resume` (снимает паузу и сбрасывает напоминания), `NotifyAckFailed`/`AckFailNotified` (о неудачном авто-ack сказано в этом ходе); `Clear` — удалить файлы сессии. Журнал хранит `Version` (сейчас 1): `Save` проставляет её, `LoadJournal` для другой версии (или файла без версии) возвращает пустой журнал без ошибки.
- `ValidID(id)` — id сессии не пуст после `strings.TrimSpace`.
- `RemoveStale(root, maxAge, now)` — все обычные файлы state-dir старше `maxAge`, а снимки (`.snapshot`) — старше меньшего из `maxAge` и 24 ч; каталоги и их содержимое не трогает.

## Инварианты и подводные камни
- Формат снимка — заголовок `auto-context snapshot 1` и записи `<mtime> <size> <путь>\0`: пути могут содержать пробелы и переводы строк. `Save` пишет записи по порядку путей; файлы того же формата, записанные раньше в порядке карты (возможно, с повтором пути), `LoadSnapshot` сортирует при загрузке, повтор — побеждает последняя запись (`TestSnapshotLoadsUnsorted`). Формат не менялся, поэтому старые снимки читаются как раньше.
- Списки журнала — отсортированные множества: `LoadJournal` и `Save` нормализуют их (включая `AckFailNotified`), как бы журнал ни был собран.
- `Clear` удаляет только после `fsutil.Resolve`: state-dir, ведущий наружу, не даёт удалить чужой файл.
- Файлы сессии удаляет SessionEnd; оставшиеся от сессий без SessionEnd (сбой, kill) — `RemoveStale` в SessionStart.
- Запись без fsync (`fsutil.WriteState`): файлы восстановимы. Лимит чтения — `MaxSize` (256 МиБ).
- Сравнение по mtime+size: правка того же размера в ту же наносекунду не видна.
