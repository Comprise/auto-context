# internal/logx
Дописывает ошибки хуков в `.auto-context/log`, никогда не падая.

## Назначение
Хук не должен ломать Claude Code и засорять stdout (там JSON-ответ): ошибки идут в лог проекта, а если лог недоступен — в stderr.

## Публичный API / точки входа
- `Errorf(root, format, args...)` — одна строка `<RFC3339Nano> <сообщение>`; управляющие и форматные символы — пробелы (`textx.Clean`).
- `Entries(root)` — метки времени записей `log.1` и `log` (для `status` и SessionStart); `Writable(root)` — можно ли дописать лог, ничего не записав: существующий открывает на дозапись, для отсутствующего создаёт (`os.CreateTemp`, `log.probe-*`) и удаляет пробный файл рядом (сам лог не трогает — его может создавать другой хук); без каталога `.auto-context` — nil. `log.1` тоже проверяется через `fsutil.Resolve`.
- `Stderr` — приёмник записей, которые не удалось записать.

## Инварианты и подводные камни
- Ротация после 1 МиБ в `log.1` — под блокировкой `log.lock` с повторной проверкой размера: из параллельных хуков, увидевших переполненный лог, ротирует только первый, остальные дописывают в свежий (иначе вторая ротация затёрла бы `log.1` почти пустым логом). Блокировка — `filelock.Lock` по лексическому пути `.auto-context/log.lock` после проверки `fsutil.Resolve` (flock на unix, `O_EXCL` на остальных ОС; симлинк или FIFO на месте lock-файла отвергается — это сбой ротации; см. context/internal/filelock.md). Ожидание не дольше `filelock.Wait` (500 мс): не дождался — ротация пропускается, запись всё равно дописывается. Сбой открытия блокировки — тоже сбой ротации.
- Сбой ротации пишется в сам лог отдельной записью — он считается ошибкой; повторно — только если в последних 64 КиБ лога такой записи нет, чтобы не удваивать счёт.
- Если каталога `.auto-context` нет (в активном проекте — вызывающий проверяет активность), запись создаёт его через `fsutil.EnsureStateDir`, вместе с `.gitignore`; сбой этого не мешает записи (дальше `MkdirAll`).
- Лог пишется только после `fsutil.Resolve` и только в обычный файл (FIFO заблокировал бы хук).
- Однострочность записей — контракт для `Entries`.
- Сама дозапись идёт без блокировки: `O_APPEND` защищает отдельные записи; хук, открывший лог до ротации, допишет в `log.1` — запись не теряется.

## Связи
Зависит от: `internal/filelock`, `internal/fsutil`, `internal/textx`.
Используется в: `cmd/auto-context`, `internal/hooks`.
