# internal/config
Читает, валидирует и правит необязательный `.auto-context/config.yaml`, ищет корень репозитория.

## Назначение
Настройки обнаружения юнитов и уведомлений. Файл необязателен и коммитится; он может прийти из чужого репозитория, поэтому значения проверяются.

## Публичный API / точки входа
- `FileName` (`.auto-context/config.yaml`), `MaxSize` (1 МиБ), `Config`, `Default()`; `track` — шаблоны файлов без кодового расширения, которые считаются исходниками.
- `Load(root)` → `(Config, Problems, error)` — значения по умолчанию плюс файл; плохие настройки отбрасываются и перечисляются в `Problems` (nil, если их нет), остальное применяется; нечитаемый или неразбираемый файл — `Default()` и ошибка.
- `Problems` не цитируют значения из файла (они попадают в контекст Claude): неизвестный ключ — только короткое слово из строчных букв, иначе «(name not shown)»; ошибка типа — «line N: a value of the wrong type»; плохой элемент списка — «<ключ> entry <номер> (<причина>)». `Describe(err)` — причина ошибки загрузки без текста файла: «a YAML syntax error at line N» или фиксированная категория.
- `ValidatePattern(p)` — синтаксис doublestar, ≤256 байт, ≤8 групп `{}`; `(*Config).Validate()` — те же проверки для конфига, собранного в коде.
- `ValidLanguage` — код языка доков (`^[A-Za-z]{2,3}(-[A-Za-z0-9]{2,8}){0,2}$`): значение показывается Claude.
- `AddExclude(root, pattern)` — дописывает шаблон в `exclude`, правит только этот ключ; создаёт файл и каталог (через `fsutil.EnsureStateDir`).
- `FindRoot(cwd)` — ближайший сверху каталог с `.git` или `FileName`, принадлежащими текущему пользователю.

## Устройство и потоки данных
`Load`: `fsutil.ReadFile` с лимитом; неизвестные ключи ищутся отдельным разбором в map; `yaml.Unmarshal` поверх `Default()` (ошибки типа — в Problems, поле остаётся по умолчанию); `fix()` заменяет null-списки значениями по умолчанию и чистит значения: `min_files ≥ 1`, `max_session_notice` 0..100, расширения с точкой, маркеры — имена файлов, шаблоны через `ValidatePattern`.
`AddExclude` разбирает все YAML-документы в `yaml.Node`, дописывает элемент в последовательность `exclude` (или добавляет ключ со списком по умолчанию плюс шаблон) и пишет атомарно.

## Инварианты и подводные камни
- Только синтаксическая ошибка YAML или нечитаемый файл дают `Default()` целиком; одна опечатка не отменяет `include`/`exclude` пользователя.
- Лимиты на шаблоны нужны против экспоненциального разбора `{a,aa}{a,aa}…` в doublestar на каждом хуке.
- Если в списке не осталось валидных элементов, берётся значение по умолчанию, а не пустой список.
- Заданный список заменяет значение по умолчанию целиком; поэтому `AddExclude` без ключа `exclude` записывает весь список по умолчанию.
- `AddExclude` сохраняет комментарии (в том числе у элементов списка), прочие ключи, файл из одних комментариев и дальнейшие YAML-документы; отступы нормализуются до 2 пробелов. Верхний уровень — не mapping — ошибка.
- `FindRoot` не поднимается в `$HOME` из подкаталогов (иначе `~/.auto-context/config.yaml` или dotfiles-`~/.git` делали бы корнем весь дом) и не доверяет меткам чужого владельца (общий `/tmp`); без меток возвращает cwd.
