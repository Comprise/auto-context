# internal/config
Читает, валидирует и правит необязательный `.auto-context/config.yaml`, ищет корень репозитория.

## Назначение
Настройки обнаружения юнитов и уведомлений. Файл необязателен и коммитится; он может прийти из чужого репозитория, поэтому значения проверяются.

## Публичный API / точки входа
- `FileName` (`.auto-context/config.yaml`), `MaxSize` (1 МиБ), `Config`, `Default()`; `Config.DiscoveryReset` (`yaml:"-"`) — `Load`/`Validate` отбросили или сбросили настройку, от которой зависят юниты (`include`, `exclude`, `track`, `min_files`, `code_extensions`, `module_markers`: плохой элемент, неверный тип, повторный ключ): юниты не такие, как просит файл; `index_file` — имя индексного файла юнитов, `IndexClaude` (`CLAUDE.md`, по умолчанию) или `IndexAgents` (`AGENTS.md`, Codex); `track` — шаблоны файлов без кодового расширения, которые считаются исходниками.
- `Load(root)` → `(Config, Problems, error)` — значения по умолчанию плюс файл; плохие настройки отбрасываются и перечисляются в `Problems` (nil, если их нет), остальное применяется; нечитаемый или неразбираемый файл — `Default()` и ошибка.
- `Problems` не цитируют значения из файла (они попадают в контекст Claude): неизвестный ключ — только короткое слово из строчных букв, иначе «(name not shown)»; ошибка типа — «line N: <ключ> has a value of the wrong type»; повторный ключ — «line N: duplicate key <ключ>»; плохой элемент списка — «<ключ> entry <номер> (<причина>)», причина — фиксированный текст из проверки (`check` возвращает `(reason, ok)`), для шаблонов всегда «invalid pattern». `Describe(err)` — причина ошибки загрузки без текста файла: «a YAML syntax error at line N» или фиксированная категория.
- `ValidatePattern(p)` — синтаксис doublestar, ≤256 байт, ≤8 групп `{}` (текст ошибки цитирует шаблон — только для CLI, не для `Problems`); `EscapePattern(dir)` — шаблон, совпадающий с `dir` буквально (`\ * ? [ ] { }` экранируются обратной косой); `(*Config).Validate()` — те же проверки для конфига, собранного в коде.
- `ValidLanguage` — код языка доков (`^[A-Za-z]{2,3}(-[A-Za-z0-9]{2,8}){0,2}$`): значение показывается Claude.
- `AddExclude(root, pattern)` — дописывает шаблон в `exclude`, правит только этот ключ; создаёт файл и каталог (через `fsutil.EnsureStateDir`). Конфиг, который не загружается (в том числе битый следующий YAML-документ), — ошибка `.auto-context/config.yaml cannot be used: <Describe>`, файл не меняется.
- `FindRoot(cwd)` — ближайший сверху каталог с `.git` или `FileName`, принадлежащими текущему пользователю; `$HOME` и каталоги сравниваются после `filepath.Clean` и `EvalSymlinks` (слеш в конце или симлинк в `HOME` не обходят защиту), возвращаемый путь — от исходного `cwd`.

## Устройство и потоки данных
`Load`: `fsutil.ReadFile` с лимитом; текст разбирается один раз в `yaml.Node` (`parse`), читается первый документ. `topKeys` идёт по ключам верхнего уровня: неизвестные (в том числе внутри отображений под `<<`) — в Problems, повторный ключ — проблема «duplicate key», действует первое значение; остальные пары и все ключи слияния `<<` декодируются одним отображением поверх `Default()` (`decode`), так что слияние — по правилам yaml.v3: явный ключ сильнее слитого при любом порядке. При ошибке типа каждая пара проверяется отдельно, и поле той, что не разбирается сама по себе, сбрасывается к значению по умолчанию (`reset`): yaml.v3 оставляет поле разобранным наполовину, например пустой `exclude` при `[{a: b}]`; у `<<` проверяются слитые пары, поле явного ключа не сбрасывается. Верхний уровень не отображение — `Default()` и проблема «the top level is not a mapping»; `fix()` заменяет null-списки значениями по умолчанию и чистит значения: `min_files ≥ 1`, `max_session_notice` 0..100, расширения с точкой, маркеры — имена файлов, шаблоны через `ValidatePattern`.
`AddExclude` разбирает все YAML-документы в `yaml.Node` и правит первый ключ `exclude` первого документа (`setExclude`): в годный список дописывает элемент, иначе (не список, alias, список без валидных элементов) ставит новый список «действующее значение плюс шаблон»; ключ через alias становится обычным, alias'ы на якоря внутри старого значения заменяются копиями — другие ключи (`track: *ex`) не меняются; без ключа добавляет его со списком по умолчанию плюс шаблон. Затем выбирает текст: если текстовая правка (`textEdit`: строка `- шаблон` после последнего элемента блочного списка или ключ в конце файла из одного документа) загружается в тот же `Config`, что и перекодированный узел, берётся она — пустые строки, `%YAML`, отступы и CRLF сохраняются; иначе перекодированный файл с возвращёнными директивами и пустыми строками перед ключами верхнего уровня (`keepLayout`, тоже со сверкой), в крайнем случае — просто перекодированный. Пишет атомарно, сохраняя права существующего файла (новый — 0644).

## Инварианты и подводные камни
- `index_file` не из двух допустимых имён — `Default()` и `ErrBadIndexFile` (как неразбираемый файл; `Describe` называет причину): от имени зависит, где лежат все доки, угадывать нельзя. Пустое значение — по умолчанию. Тем же `ErrBadIndexFile` кончаются `index_file` не строкой (отображение, список, в том числе под `<<`), а также заданный дважды — единственный повторный ключ, который ломает файл, а не даёт проблему.
- Только синтаксическая ошибка YAML или нечитаемый файл дают `Default()` целиком; одна опечатка не отменяет `include`/`exclude` пользователя.
- Лимиты на шаблоны нужны против экспоненциального разбора `{a,aa}{a,aa}…` в doublestar на каждом хуке.
- Если в списке не осталось валидных элементов, берётся значение по умолчанию, а не пустой список.
- Заданный список заменяет значение по умолчанию целиком; поэтому `AddExclude` без ключа `exclude` записывает весь список по умолчанию.
- Если в записанном `exclude` нет ни одного валидного шаблона (или элементы не той формы), `Load` берёт список по умолчанию; `AddExclude` тогда заменяет последовательность действующим списком плюс шаблон, а не дописывает в неё — иначе значения по умолчанию пропали бы. Если хоть один элемент валиден, шаблон дописывается.
- `AddExclude` сохраняет комментарии (в том числе у элементов списка), прочие ключи, файл из одних комментариев и дальнейшие YAML-документы; при перекодировании отступы нормализуются до 2 пробелов. Верхний уровень — не mapping — ошибка. yaml.v3 не принимает `%YAML 1.2` (только 1.1).
- `FindRoot` не поднимается в `$HOME` из подкаталогов (иначе `~/.auto-context/config.yaml` или dotfiles-`~/.git` делали бы корнем весь дом) и не доверяет меткам чужого владельца (общий `/tmp`); без меток возвращает cwd.
