# internal/units
Находит юниты документации в репозитории и классифицирует пути.

## Назначение
Юнит — каталог, который по `include`, маркеру модуля или `min_files` получает пару доков: индексный файл `<unit>/<index_file>` (`CLAUDE.md` или `AGENTS.md` из конфига) + `context/<unit>.md` (доки могут отсутствовать). Пакет — единственный источник истины о структуре: какие каталоги юниты, какие файлы им принадлежат, к какому виду относится путь.

## Публичный API / точки входа
- `Discover(root, cfg)` → `*Tree`; `RootUnit` (`_root`); `Reason` (`root`/`include`/`module`/`files`).
- `Tree` (не для параллельного использования: сопоставление `.gitignore` тратит общий бюджет): юниты и их файлы, принадлежность файла юниту, отслеживаемые файлы, их mtime/size (`Stat`/`Stats`), предупреждения и их полное число (`WarningCount`).
- `Tree.Classify(rel)` — `KindCode`, `KindIndexDoc`, `KindContextDoc`, `KindIgnore`.
- `ContextPath(unit)` — путь `context/<unit>.md`; `Tree.IndexFile()` — имя индексного файла из конфига; `SafeName(p)` — путь можно показывать как есть (правило имён юнитов, см. ниже).

## Устройство и потоки данных
- Файлы: `units.go` — дерево, `Classify`, `SafeName`; `walk.go` — `Discover`, обход без git, `classifyFile`/`addFile`; `ignore.go` — разбор и сопоставление `.gitignore` и шаблонов конфига, лимиты; `gitfiles.go` — список файлов от git.
- Класс файла (`classifyFile` → `fileClass`: контекст-док, индексный файл, маркер, исходник) — единственное место, где решается, что файл значит; `interesting` и `addFile` берут его оттуда. Маркер и исходник контекст-дока не бывают, исходник — ещё и индексным файлом.
- Внутри git work tree (корень может быть его подкаталогом) список — `git ls-files -co --exclude-standard -z` через `gitx`, stat нужных файлов — параллельно (воркеры берут индексы по атомарному счётчику, от stat хранятся только режим, mtime и размер); вывод git разбирается без копии всего списка в строку. Вне git — `filepath.WalkDir` со своим разбором `.gitignore`.
- Обход вместо git: git нет или это не репозиторий (тихо); git упал, или корень игнорируется внешним репозиторием (пустой список при `check-ignore .`) — с предупреждением; если после пустого списка упал сам `check-ignore`, — тоже обход с предупреждением (пустой список убрал бы все юниты и оглавление). Lstat каталога из индекса с ошибкой, кроме «нет» и ENOTDIR, — предупреждение. Таймаут git и список больше 256 МиБ — ошибка (`ErrGitTimeout`, `ErrListTooLarge`): обход такого дерева не уложится в таймауты хуков.
- Проверка правил игнора и Lstat — только для файлов, которые могут значить: доки, маркеры, исходники.
- Исходник: совпадает с `track`, является маркером модуля (`go.mod`, `package.json`…: зависимости — часть юнита) или имеет расширение из `code_extensions` и не `.md`.
- Причина юнита: `include`, затем `module` (маркер не под игнором), затем `files` (не меньше `min_files`).
- `exclude` и `track` компилируются один раз: литералы, `X/**` и `**/X/**` проверяются строковыми операциями, остальное — doublestar.

## Инварианты и подводные камни
- Режимы git и обхода дают одно и то же (`TestDiscoverGitMatchesWalk`, `TestGitignoreSemanticsMatchGit`, `TestGitignoreMoreFormsMatchGit`), кроме исключений, известных только git (`.git/info/exclude`, глобальные), и уже закоммиченных файлов под `.gitignore`. Каталог в обоих режимах существует, только если в нём (или ниже) есть неигнорируемый и неисключённый файл: пустой или целиком игнорируемый каталог не даёт юнита (`TestDiscoverEmptyDirsMatchGit`); правила `*<суффикс>` сравниваются с неэкранированным суффиксом (`TestGitignoreBraceSuffixMatchesGit`).
- Разбор `.gitignore` (`parseIgnore`): решает самый глубокий файл со сработавшим правилом, внутри файла — последнее совпавшее; файл в игнорируемом каталоге игнорируется; `X/**` не задевает сам `X`; `{}` — литерал, как в git; BOM снимается. Имена, `*.расширение` (индекс по расширению) и `*<суффикс>` — поиск и сравнение строк; остальные правила — doublestar после литерального префильтра по началу, концу и самому длинному литералу в середине; `**/` может означать ноль каталогов, поэтому ведущий `/` после него в префильтре не требуется.
- `.gitignore`, который не обычный файл, больше 256 КиБ, 5000 правил (10000 всего) или 1000 правил, проверяемых doublestar (с `/` или шаблоном сложнее `*<суффикс>`), пропускается с предупреждением; некорректные правила и правила-шаблоны длиннее 512 байт (`maxRuleLen`) отбрасываются с предупреждением. Работа doublestar за `Discover` ограничена бюджетом `maxGlobWork` (сумма «длина шаблона × длина пути», около секунды); сверх него правила с шаблонами пропускаются с одним предупреждением.
- Предупреждения попадают в контекст Claude через `auto-context status`, поэтому в них нет текста из репозитория: путь — только прошедший `SafeName` (иначе «a path with unusual characters»), ошибка — фиксированная категория (`errKind`), сбой git — `gitx.Brief`.
- Имя юнита — буквы, цифры, Unicode-знаки (Mark), пробел и `._-@+/`; каталог `_root` юнитом не бывает.
- `exclude` вида `X/**` отсекает каталог целиком; простое имя каталога лишает его только статуса юнита.
- Пропускаются: симлинки (кроме context-дока, ведущего на `.md` в репозитории, — для него берётся stat цели), сабмодули, удалённые файлы (и ENOTDIR), каталоги, оставшиеся только в индексе, любой каталог `.git`. Нечитаемые записи — с предупреждением (в списке не больше 20).
- Каталоги `context`, `context/*`, `.auto-context` юнитами не бывают; о коде внутри `context/` — одно предупреждение. Пути везде через `/`.
- `Discover` проверяет переданный `Config` (`Validate`), даже если он собран в коде.
