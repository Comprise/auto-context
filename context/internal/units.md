# internal/units
Находит юниты документации в репозитории и классифицирует пути.

## Назначение
Юнит — каталог, который по `include`, маркеру модуля или `min_files` получает пару доков: индексный файл `<unit>/<index_file>` (`CLAUDE.md` или `AGENTS.md` из конфига) + `context/<unit>.md` (доки могут отсутствовать). Пакет — единственный источник истины о структуре: какие каталоги юниты, какие файлы им принадлежат, к какому виду относится путь.

## Публичный API / точки входа
- `DiscoverContext(ctx, root, cfg)` → `*Tree` в пределах `ctx`: уже закончившийся `ctx` и конец `ctx` во время обхода без git (проверка каждые 256 записей, `walkCheckEvery`) — `ErrTimeUp`, конец во время вызова git — `ErrGitTimeout`; `RootUnit` (`_root`); `Reason` (`root`/`include`/`module`/`files`). `Discover(root, cfg)` — обёртка без ограничения по времени, помечена устаревшей и оставлена только для тестов `internal/docstate`.
- `Tree` неизменяем после `DiscoverContext` и читается из нескольких горутин (`TestTreeConcurrentReads` под `-race`); даёт два вида:
  - «полный» — `Units`, `Files`, `Tracked`, `StatsView`/`Stat`, `IsUnit`, `UnitOf`, `Classify`: отслеживаемые и неотслеживаемые неигнорируемые файлы; по нему работают хуки, `status`, оглавление;
  - «индексный» — `HashFiles(unit)` (файлы юнита только из индекса git; `nil`, если `unit` не юнит этого вида) и `HashUnits()` (юниты этого вида без `_root`, отсортированы): вход `source_hash` схемы v2. Неотслеживаемые файлы и локальные исключения (`.git/info/exclude`, глобальные) его не меняют, поэтому хэш в рабочей копии совпадает с хэшем чистого клона (A-H1). Каталог, ставший юнитом только из-за неотслеживаемых файлов, юнит полного вида, но не индексного; его отслеживаемые файлы в индексном виде относятся к родительскому юниту или `_root`. В режиме обхода оба вида совпадают.
  - Ещё: предупреждения и их полное число (`WarningCount`).
- `ErrUnknownUnit` — сигнальная ошибка «нет такого юнита»; вызывающие оборачивают её через `%w`.
- `ErrGitTimeout`, `ErrListTooLarge`, `ErrTimeUp` — ошибки `Discover` (см. ниже; `ErrTimeUp` — кончился бюджет хука или команда прервана).
- `Tree.Classify(rel)` — `KindCode`, `KindIndexDoc`, `KindContextDoc`, `KindIgnore`. Каждый вызов берёт свой сопоставитель со своим бюджетом glob и ничего не пишет в дерево: предупреждения и бюджет после любого числа вызовов те же (`TestClassifyDoesNotMutate`). Для разовых проверок.
- `Tree.Classifier()` → `*Classifier` с `Classify(rel)`: один бюджет `maxGlobWork` и одна память `skipDir` на все вызовы, дерево не трогает, не для параллельного использования. Для проходов по многим путям (Stop по diff хода): свежий бюджет на каждый вызов снял бы общую границу, и враждебные правила в режиме обхода вывели бы хук за его бюджет (`TestClassifierSharesBudget`).
- `Tree.StatsView()` — карта путь → `filestat.Stat` самого дерева, без копии (на больших деревьях копия — заметная доля памяти хука); вызывающий её не меняет. `Stat(rel)` читает ту же карту.
- `ContextPath(unit)` — путь `context/<unit>.md`; `Tree.IndexFile()` — имя индексного файла из конфига; `SafeName(p)` — путь можно показывать как есть (правило имён юнитов, см. ниже).

## Устройство и потоки данных
- Файлы: `units.go` — дерево, `Classify`, `SafeName`; `walk.go` — `DiscoverContext`, состояние обнаружения (`discovery`), обход без git, `classifyFile`/`addFile`; `ignore.go` — разбор и сопоставление `.gitignore` и шаблонов конфига (`patterns`, `matcher`), лимиты; `gitfiles.go` — список файлов от git.
- Разделение состояния: `patterns` — скомпилированные `exclude`/`track` и загруженные `.gitignore`; их заполняет обнаружение, потом они только читаются (дерево держит на них ссылку). `matcher` — то, что тратит сопоставление: остаток бюджета doublestar, флаг предупреждения о бюджете, память `skipDir` и куда писать предупреждения. Обнаружение (`discovery`: дерево в постройке, его `matcher`, счётчики правил, флаг предупреждения о коде в `context/`) живёт только внутри `DiscoverContext`; `Tree.Classify` создаёт `matcher` на вызов без памяти `skipDir`, `Classifier` — один на свой срок жизни с памятью; предупреждения обоих отбрасываются.
- Класс файла (`classifyFile` → `fileClass`: контекст-док, индексный файл, маркер, исходник) — единственное место, где решается, что файл значит; `interesting` и `addFile` берут его оттуда. Маркер и исходник контекст-дока не бывают, исходник — ещё и индексным файлом.
- Сначала `gitx.WorkTreeOK`: git должен работать над деревом самого проекта (корень — top level или под ним; git-каталог внутри, связанный worktree или сабмодуль). Если `core.worktree` или `.git`-файл уводят git в чужое дерево или репозиторий, — обход с предупреждением «git's work tree or git dir lies outside the project» (S-4; `TestDiscoverForeignWorkTreeWalks`); связанный worktree и сабмодуль остаются в режиме git (`TestDiscoverInLinkedWorktreeUsesGit`).
- Внутри своего git work tree (корень может быть его подкаталогом) список — `git -c core.untrackedCache=true ls-files -co --exclude-standard -t -z` через `gitx` (`core.untrackedCache` лишь разрешает git пользоваться расширением индекса, если оно есть); тег `?` — неотслеживаемый файл, остальные (`H`, `S`, `M`…) — записи индекса. Квалификация юнитов и приписывание файлов (`view`) выполняются дважды: по всему списку и по записям индекса (если неотслеживаемых нет, второй вид — тот же объект). Существование каталога в индексном виде тоже берётся только из записей индекса. Stat нужных файлов — параллельно (воркеры берут индексы по атомарному счётчику, от stat хранятся только режим, mtime и размер); вывод git разбирается без копии всего списка в строку. Вне git — `filepath.WalkDir` со своим разбором `.gitignore`.
- Обход вместо git: git нет или это не репозиторий (тихо); git упал, или корень игнорируется внешним репозиторием (пустой список при `check-ignore .`) — с предупреждением; если после пустого списка упал сам `check-ignore`, — тоже обход с предупреждением (пустой список убрал бы все юниты и оглавление). В режиме git файл из списка учитывается, только если все каталоги над ним — настоящие каталоги (каждый lstat'ится один раз, с памятью): отслеживаемый каталог, заменённый симлинком, файлом или удалённый, скрывает всё, что git под ним перечисляет, — как в обходе, и ничего вне репозитория не читается (`TestDiscoverGitSkipsSymlinkedTrackedDir`). Каталог берётся только из файла, который есть в рабочем дереве (не симлинк): индекс помнит и удалённые файлы. Для нужных файлов это уже известно из параллельного stat, остальные lstat'ятся, лишь пока их каталог не известен. Ошибка lstat, кроме «нет» и ENOTDIR, — предупреждение о каталоге. Сбой `rev-parse` или `ls-files` при `.git` в корне — обход с предупреждением «git rev-parse failed (…)»/«git ls-files failed (…)»; без `.git` ответ «not a git repository» (`gitx.NotRepo`) или отсутствие git — тихий обход.
- Лимиты: больше `maxFiles` = 800 000 файлов (в режиме git — записей списка, в режиме обхода — обычных файлов в непропущенных каталогах) или больше 256 МиБ вывода git — `ErrListTooLarge`; таймаут git — `ErrGitTimeout`. Текст `ErrGitTimeout` называет обе причины: репозиторий слишком большой или медленный, либо `.gitignore`/файл исключений — не обычный файл (FIFO, устройство: git блокируется на чтении, `TestDiscoverGitFIFOGitignore`). В обход при этих ошибках не переходим: обход дерева, которое git не перечислил вовремя, тоже не уложится в таймауты хуков.
- Проверка правил игнора и Lstat — только для файлов, которые могут значить: доки, маркеры, исходники.
- Исходник: совпадает с `track`, является маркером модуля (`go.mod`, `package.json`…: зависимости — часть юнита) или имеет расширение из `code_extensions` и не `.md`.
- Причина юнита: `include`, затем `module` (маркер не под игнором), затем `files` (не меньше `min_files`).
- `exclude` и `track` компилируются один раз: литералы, `X/**` и `**/X/**` проверяются строковыми операциями, остальное — doublestar.

## Инварианты и подводные камни
- Режимы git и обхода дают одно и то же (`TestDiscoverGitMatchesWalk`, `TestGitignoreSemanticsMatchGit`, `TestGitignoreMoreFormsMatchGit`), кроме исключений, известных только git (`.git/info/exclude`, глобальные), и уже закоммиченных файлов под `.gitignore`. Каталог в обоих режимах существует, только если в нём (или ниже) есть неигнорируемый и неисключённый файл: пустой или целиком игнорируемый каталог не даёт юнита (`TestDiscoverEmptyDirsMatchGit`), как и каталог, чьи файлы из индекса удалены с диска (`TestDiscoverGitSkipsDirsOfDeletedFiles`); правила `*<суффикс>` сравниваются с неэкранированным суффиксом (`TestGitignoreBraceSuffixMatchesGit`).
- Разбор `.gitignore` (`parseIgnore`): решает самый глубокий файл со сработавшим правилом, внутри файла — последнее совпавшее; файл в игнорируемом каталоге игнорируется; `X/**` — только внутри `X`: проверяется совпадение `X` с каждым собственным префиксом-каталогом пути (`matchInside`), сам `X` не задевается; `{}` — литерал, как в git; BOM снимается. Классы `[...]` переписываются по членам, как их читает wildmatch git (`globPattern`/`bracketClass`): `]` первым — член класса, обратный диапазон держит свой первый конец, класс никогда не совпадает с `/` (`/` выкидывается из членов, у отрицания — добавляется); класс без членов — правило ни с чем не совпадает, без предупреждения (`TestGitignoreBracketEdgesMatchGit`). POSIX-классы `[:name:]` — все 12 из wildmatch git (`alnum alpha blank cntrl digit graph lower print punct space upper xdigit`), как ASCII-диапазоны; `[:` без `:]` — обычный член `[`; неизвестное имя (`[[:foo:]]`) — правило ни с чем не совпадает, без предупреждения; `-` после класса — литерал (`TestIgnorePOSIXClasses`). Перед разбором `normalizeRule`: серия из 2+ `*` — `**` между слешами, иначе `*` (`***`, `TestIgnoreTripleStar`); `**/**` → `**`; `\/` → `/`; `**\/` → `*/**`. Правила, которые git никогда не сопоставит (`//` вне класса, ведущий `/`, оставшийся после снятия первого, `/` в конце после снятия одного), молча отбрасываются. Перевод идёт по байтам: байты не в UTF-8 (`.gitignore` в Latin-1) сохраняются как написаны и совпадают с теми же байтами в именах, как в git (`TestGitignoreNonUTF8Rules`). Имена, `*.расширение` (индекс по расширению) и `*<суффикс>` — поиск и сравнение строк; остальные правила — doublestar после литерального префильтра по началу, концу и самому длинному литералу в середине; `**/` может означать ноль каталогов, поэтому ведущий `/` после него в префильтре не требуется.
- `.gitignore`, который не обычный файл, больше 256 КиБ, 5000 правил (10000 всего) или 1000 правил, проверяемых doublestar (с `/` или шаблоном сложнее `*<суффикс>`), пропускается с предупреждением; некорректные правила и правила-шаблоны длиннее 512 байт (`maxRuleLen`) отбрасываются с предупреждением. Работа doublestar за `DiscoverContext` ограничена бюджетом `maxGlobWork` (сумма «длина шаблона × длина пути», около секунды); сверх него правила с шаблонами пропускаются с одним предупреждением. У каждого вызова `Tree.Classify` и у каждого `Classifier` такой же бюджет свой, без предупреждения.
- Предупреждения попадают в контекст Claude через `auto-context status`, поэтому в них нет текста из репозитория: путь — только прошедший `SafeName` (иначе «a path with unusual characters»), ошибка — фиксированная категория (`errKind`), сбой git — `gitx.Brief`.
- Имя юнита (`SafeName`) — буквы, цифры, Unicode-знаки (Mark) и `._-@+/`, без пробела; ни один сегмент не начинается с `-` (читался бы как опция); не длиннее 128 байт, сегмент — 64; каталог `_root` юнитом не бывает. Каталог с другим именем не юнит: его файлы уходят в родительский юнит или `_root`, его доки становятся сиротами (`TestSafeNameRules`, `TestSpaceDirNoLongerUnit`; так стало и с каталогами с пробелом, бывшими юнитами).
- `exclude` вида `X/**` отсекает каталог целиком; простое имя каталога лишает его только статуса юнита.
- Пропускаются: симлинки (кроме context-дока, ведущего на `.md` в репозитории, — для него берётся stat цели), сабмодули, удалённые файлы (и ENOTDIR), каталоги без существующих файлов, любой каталог `.git`. Обход не заходит и в каталог, где есть `.git` любого вида (каталог, файл, симлинк: вложенный репозиторий, worktree, сабмодуль; `nestedRepo`, `TestWalkSkipsNestedRepo`), — git там тоже ничего не перечисляет; корень не проверяется. Нечитаемые записи — с предупреждением (в списке не больше 20).
- В режиме обхода нужные файлы собираются во время `WalkDir`, а lstat'ятся потом параллельно (`parallelLstat`), как в режиме git.
- Сопоставитель `.gitignore` проверяется дифференциальным фазз-тестом против git (`FuzzIgnoreMatchesGit`, `fuzz_test.go`: два правила и путь из алфавита ``ab*?[]!-\/.^``, сравнение с `git check-ignore --no-index`); найденные расхождения лежат регрессионными сидами в `testdata/fuzz/FuzzIgnoreMatchesGit/`. `BenchmarkDiscover` — 20 000 отслеживаемых файлов в 500 юнитах.

## Известные ограничения
- Режим обхода — запасной: `?` и классы `[...]` в нём сопоставляются по рунам (doublestar), а wildmatch git — по байтам, поэтому на не-ASCII именах `?` и отрицательные классы могут разойтись с git (CO-4). Переписывать сопоставитель ради запасного режима не стали.
- Режим обхода сопоставляет `.gitignore` с учётом регистра, как git с `core.ignorecase=false`. На файловых системах без регистра (macOS, Windows) `git init` ставит `core.ignorecase=true`, и список от git тогда игнорирует без учёта регистра; запасной обход, у которого нет репозитория и его настройки, может разойтись с ним на правилах вроде `[[:upper:]]` или `*.GO`. Сравнивающие с git тесты (`gitInit`, `FuzzIgnoreMatchesGit`) ставят `core.ignorecase=false`.
- Таймаут git (`ErrGitTimeout`) не переходит в обход: дерево, которое git не перечислил вовремя, обход тоже не перечислит в таймаут хука, поэтому, пока причина не устранена (большой каталог не в `.gitignore`, FIFO вместо `.gitignore`), каждый хук ждёт таймаут git и сообщает об ошибке (T-H2). Исправлены только текст ошибки и тесты.
- Каталоги `context`, `context/*`, `.auto-context` юнитами не бывают; о коде внутри `context/` — одно предупреждение. Пути везде через `/`.
- `DiscoverContext` проверяет переданный `Config` (`Validate`), даже если он собран в коде.
