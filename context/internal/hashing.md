# internal/hashing
Считает source_hash юнита по списку файлов с кешем mtime/size.

## Назначение
Отпечаток исходников юнита; по нему решается, устарела ли документация. Кеш избавляет от перечитывания неизменённых файлов на каждом хуке.

## Публичный API / точки входа
- `SourceHash(root, files, extra, c)` — `sha256:<hex>` от строк `relpath\x00sum\n` по отсортированным файлам и `\x00unit\x00<extra>\n` по отсортированным extra.
- `NewCache`, `LoadCache(root)` → кеш и ошибка, если файл непригоден.
- `Cache.Prewarm(root, files, save, every)` — параллельно хеширует изменившиеся файлы и периодически вызывает `save`; `UseStats` — доверять mtime/size из `Discover`; ещё `Prune`, `Save`, `Len`.

## Инварианты и подводные камни
- Содержимое хешируется с `\r\n` как `\n` (и на стыке чанков): чекаут с autocrlf даёт тот же отпечаток.
- Формат отпечатка записан во frontmatter всех доков: его изменение один раз делает затронутые юниты stale.
- Поля кеша закрыты: любое изменение помечает его изменённым, `Save` пишет только тогда (или если файла нет), без fsync.
- Непригодный файл кеша (битый, больше 256 МиБ) даёт пустой кеш, который перезаписывается при следующем `Save`; кеш другой версии заменяется молча.
- `UseStats`: при совпадении записи кеша со статистикой `Discover` файл не трогается; иначе `hashFile` делает Lstat и читает только обычный файл (симлинки-исходники `Discover` не отслеживает). Статистика должна быть из того `Tree`, чьи файлы хешируются в этом процессе.
- Совпадение mtime+size при изменённом содержимом даёт старый хеш — осознанный компромисс.
