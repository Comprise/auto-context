# internal/filelock
Короткие эксклюзивные блокировки файлов для параллельных процессов хуков.

## Назначение
Несколько хуков (параллельные сессии Claude Code и Codex в одном дереве) правят общие файлы в `.auto-context`. Пакет даёт одну блокировку с ограниченным ожиданием: хук никогда не виснет на ней, а убитый хук не оставляет её навсегда.

## Публичный API / точки входа
- `Lock(path) (unlock, ok, err)` — эксклюзивная блокировка файла `path` (создаётся при необходимости). Ждёт не дольше `Wait`, опрашивая каждые 5 мс; не дождался — `ok=false` без ошибки. Ошибка открытия (нет каталога, нет прав) — `err`; симлинк, FIFO или каталог на месте `path` — `fsutil.ErrNotRegular`. `unlock` снимает блокировку.
- `Wait` = 500 мс.

## Инварианты и подводные камни
- Linux/macOS/BSD (`lock_flock.go`): `flock(LOCK_EX|LOCK_NB)` в цикле; ядро снимает блокировку при гибели процесса. `flock` берётся через `SyscallConn().Control`, не через `Fd()` (файл остаётся в блокирующем режиме). Блокировки flock — на открытый файл, поэтому два `Lock` одного пути исключают друг друга и внутри одного процесса.
- Windows и прочие (`lock_excl.go`, `lock_other.go`): блокировка — сам файл, созданный с `O_EXCL` и удаляемый `unlock`. Файл старше 10 с (`staleAfter`) считается брошенным убитым хуком и удаляется — только если это всё тот же файл (`os.SameFile` с ранее полученным `FileInfo`): свежую блокировку, подменившую его, не трогают. На Windows `FileInfo` от `Lstat` читает идентификатор файла лениво, по пути, при первом `SameFile`, поэтому он загружается сразу после проверки возраста; перед удалением файл ещё раз проверяется на возраст.
- Вызывающий проверяет путь через `fsutil.Resolve`, но передаёт **лексический** путь, не разрешённый: симлинк внутри `.auto-context` проходит `Resolve`, а блокировка через него создала бы, заблокировала или (fallback `O_EXCL`) удалила бы цель ссылки. `Lock` делает Lstat и отвергает не обычный файл; на unix открытие ещё и с `O_NOFOLLOW` — против ссылки, появившейся после проверки. `O_EXCL` сам не следует по ссылке, `unlock` удаляет саму ссылку-файл, не цель.

## Связи
Зависит от: `internal/fsutil` (`ErrNotRegular`).
Используется в: `internal/logx` (ротация лога, `log.lock`), `internal/hashing` (сохранение кеша, `cache.v5.bin.lock`).
