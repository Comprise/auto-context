# internal/hooks
Обработчики хуков Claude Code и Codex: жизненный цикл хода, обратная связь о доках.

## Назначение
Превращает JSON-событие Claude Code или Codex в необязательный JSON-ответ: напоминает обновить `context/<unit>.md` после правок кода и сообщает пользователю о проблемах, которые он должен исправить сам.

## Публичный API / точки входа
Сигнатура `func(Env, Input) ([]byte, error)`; `nil, nil` — ничего не выводить.
- `SessionStart` — статусы, оглавление, уборка старых файлов сессий, `additionalContext`: stale/missing и проблемы (конфиг, конфиг под `.gitignore` или сбой этой проверки, непригодный или несохраняемый кэш, непригодные доки, сироты — не больше 20 имён, прошедших `units.SafeName`, остальные числом (`project.ShowNames`), предупреждения обхода, ошибки индекса, нечитаемый или незаписываемый лог, ошибки хуков с прошлой сессии); `systemMessage` — о конфиге, о метке активации, ведущей наружу, или о том, что хук не может работать (`failNotice` — с фиксированной категорией причины, `SessionFailure`).
- `PromptSubmit` — снимок из `Tree.Stats()`, сброс журнала.
- `Stop` — diff со снимком, журнал, авто-ack, обратная связь (`Feedback`, `StopReason`).
- `PreToolUse` — `allow` для безопасных вызовов `auto-context`.
- `PermissionRequest` (Codex) — `behavior: allow` для тех же вызовов, только когда Codex сам собрался спросить разрешение; иначе без вывода.
- `SessionEnd` — удаляет снимок и журнал сессии без открытия проекта. В Codex не срабатывает при выходе из TUI; уборка старых файлов сессии держится на SessionStart (`session.RemoveStale`).

## Агент
`Env.Agent` (`Claude`, нулевое значение; `Codex`; `ParseAgent` для `--agent`) решает, как тексты называют навыки и команды: `Agent.Skill(name)` — `auto-context:<name>` или `$auto-context:<name>`, `Agent.Command(name)` — `/auto-context:<name>` или `$auto-context:<name>`. Имя индексного файла берётся из `Project.IndexFile()`. Stop у Codex отвечает `{"decision":"block","reason":…}` (только так Codex продолжает ход), у Claude — `additionalContext`. `Input.ToolInput` — сырой JSON; `Input.Command()` возвращает строку-команду или "", если `tool_input` другой формы (у Codex может быть массив): разбор не падает.

## Устройство Stop
`Stop` — ввод-вывод вокруг чистых шагов `recordTurn` → авто-ack (`Project.AckTouched`) → `pendingUnits` → `buildFeedback`.
1. Юниты с изменённым кодом копятся в журнале (`CodeChanged`), доки — только пути `context/<unit>.md` (`DocsTouched`); самый поздний mtime кода юнита Stop заново считает по diff со снимком начала хода.
2. Авто-ack — для доков не старше последней правки кода юнита.
3. Перед этим изменённые файлы хешируются параллельно (`Project.Prewarm`). В pending не попадают подтверждённые, уже напомненные, переставшие быть юнитами и юниты, чьи доки и так совпадают с кодом (`UpToDate`); юнит с неудачным ack попадает, даже если доки совпадают; а если о его коде уже напоминали — пока о сбое не сообщено в этом ходе (`Journal.AckFailNotified`).
4. Для каждого нового юнита (`turnNewUnits`: дока нет или `context/<u>.md` не было в снимке начала хода — в том числе для авто-ackнутого) проверяются и его родитель, и `_root`: они теряют файлы и меняют список юнитов.
5. Pending делится на: код без доков, новые юниты (Claude сначала спрашивает пользователя), context-файл со ссылкой наружу, нечитаемый context-файл, неудачный ack. В каждом сообщении не больше 20 юнитов, имена с пробелом — в кавычках.

## Инварианты и подводные камни
- Активация — `project.Active`; в неактивном проекте хуки ничего не пишут. `PreToolUse` ничего не пишет и работает в любом проекте.
- Конфиг, который не читается или не разбирается (`ConfigBroken`): Stop один раз за период поломки говорит «tracking is paused» (`Journal.ConfigNotified`), PromptSubmit не трогает снимок и помечает журнал `Paused`. Когда конфиг исправлен — в ходе или между ходами, — снимок остаётся прежним, а `Journal.Resume` сбрасывает пометки и старые напоминания: Stop видит все правки этого периода. Если снимка нет, а журнал на паузе, Stop снимает паузу без записи в лог. Нечитаемый журнал PromptSubmit и Stop логируют и начинают с пустого. Снимок PromptSubmit разбирает, только когда может его сохранить (пауза или нечитаемый журнал); нечитаемый снимок он логирует и заменяет. SessionStart в это время сообщает только о конфиге и об ошибках лога.
- Auto-ack запрещён юниту, у которого изменённый файл кода старше начала хода (mtime меньше mtime снимка): порядок с правкой доков неизвестен.
- Чистый Stop не удаляет снимок: другой Stop-хук может продолжить ход.
- Напоминание — не чаще раза на юнит за ход (`AlreadyNotified`, сброс в PromptSubmit).
- `stop_hook_active` игнорируется намеренно; от зацикливания защищает `AlreadyNotified`.
- Без снимка Stop сохраняет новый и молчит; в лог пишет «this turn's changes are not tracked», только если state-dir уже был (иначе проект включили в этом ходе). Нечитаемый или повреждённый снимок заменяется с записью в лог. Сбой первой записи журнала логируется; если не записался журнал с отметкой о напоминании, Stop молчит: иначе то же напоминание продолжало бы ход на каждом Stop.
- Правки индексного файла, включая собственные перезаписи индекса, обновлением доков не считаются.
- SessionStart считает ошибки лога до своих записей и ставит отметку после (по часам ОС, как и время в логе): о своих проблемах он сообщает сам, а не как об ошибках хуков. Текст лога Claude не читает: лог может прийти из репозитория.
- Текст конфига и логов в контекст Claude не попадает — только числа и фиксированные категории; исключение — `language`, проверенный код языка (`LanguageNote`). Причина неудачного авто-ack или отказа SessionStart — фиксированная категория (`errCategory`; для `units.ErrGitTimeout`/`ErrListTooLarge` — совет про `.gitignore`), полный текст ошибки — только в логе.
- При заданном `language` SessionStart выводит `LanguageNote` всегда, даже когда доки актуальны. Stop добавляет его к напоминаниям о коде и новых юнитах.
- `PreToolUse` и `PermissionRequest` делят `approvable`: точное совпадение `^auto-context (ack|status|units|version|changes)( [A-Za-z0-9_./-]+)*$`, без trim, без `..` и без `--exclude`; не одобряет, если `auto-context` в PATH — не бинарь плагина (`CLAUDE_PLUGIN_ROOT`) или найден через относительный элемент PATH. Без `CLAUDE_PLUGIN_ROOT` или вне PATH эта проверка не работает. На Windows `LookPath` не видит шим без расширения, поэтому одобрение блокирует только затеняющий `.bat`/`.exe` в другом каталоге PATH.
- `Agent.CLI()` — как тексты называют бинарь: у Claude `auto-context`; у Codex (в его shell `bin/` плагина не в PATH) абсолютный `$CLAUDE_PLUGIN_ROOT/bin/auto-context` (чистая `codexCLI(root)`; при символах вне `A-Za-z0-9_./-` путь целиком в одинарных кавычках, `'` как `'\''`), а при пустой переменной, неабсолютном пути, невалидном UTF-8 или управляющих символах — `auto-context`. Путь склеивается через `/` (`path.Join`) на любой ОС: это текст для POSIX-shell, а не путь для файловой системы. Все предлагаемые команды (`StopReason`, `configPaused`, SessionStart) собираются через неё. `approvable` для Codex принимает и эту форму (литеральный префикс `Codex.CLI()+" "`, в том числе в кавычках; остальные правила те же), без проверки `shadowed`.
