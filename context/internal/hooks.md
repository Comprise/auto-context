# internal/hooks
Обработчики хуков Claude Code и Codex: жизненный цикл хода, обратная связь о доках.

## Назначение
Превращает JSON-событие Claude Code или Codex в необязательный JSON-ответ: напоминает обновить `context/<unit>.md` после правок кода и сообщает пользователю о проблемах, которые он должен исправить сам.

## Публичный API / точки входа
Сигнатура `func(Env, Input) ([]byte, error)`; `nil, nil` — ничего не выводить. `Env.Ctx` — бюджет хука (git и хеширование, передаётся в `project.Open`); `nil` — без ограничения (тесты). SessionStart пишет в лог `session start: the hook's time is up: N unit(s) not hashed`, если бюджет кончился до хеширования юнитов (`TestHookBudgetStopsHashing` в cmd). Все ответы — один тип `hookOutput` (поля с `omitempty`, `hookSpecificOutput` — указатель `hookSpecific`): каждый хук пишет только свои ключи, JSON прежний байт в байт (golden-файлы в `testdata/`).
- `SessionStart` — оркестрация шагов: сразу после `load` (до любых записей в лог) — `Project.Diagnose()` (при битом конфиге — только `DiagnoseConfig()` и `LogProblems()`: о прочем SessionStart тогда не сообщает, и эти проверки не выполняются), дальше шаги выбирают свои коды (`findProblems`) и берут тексты из таблицы проекта (`Problem.Text(project.Session, Render)`): `logStatus` (лог нечитаем или не пишется; число ошибок — с прошлого SessionStart, `errorsSinceLastSession`, а не все записи, как у `Diagnose`), `configProblem` (конфиг не читается или с отброшенными настройками; у `ProblemConfigDegraded` тот же текст об отброшенных настройках), `envProblems` (конфиг под `.gitignore` или сбой этой проверки, непригодный кэш, предупреждения обхода в лог, уборка старых файлов сессий), чистая `classifyStatuses` (stale/missing/непригодные доки/число доков в старой схеме хэша — `statusGroups`), `unitProblems` (непригодные доки; «`<N> unit(s) were acked by an older auto-context; run `<cli> ack --upgrade`.`»; сироты — не больше 20 имён, прошедших `units.SafeName`, остальные числом (`project.ShowNames`); число предупреждений обхода — один текст на все `ProblemDiscoverWarning`), `indexProblems` (если `Diagnose` уже нашёл непригодное оглавление и конфиг не деградирован, показывается найденное, а `UpdateIndex` не вызывается — он отказал бы по той же причине; иначе ошибка `UpdateIndex` → `project.IndexProblem`; `ErrConfigDegraded` — `ProblemIndexPaused` «индекс и auto-ack на паузе», без записи в лог), `cacheSaveProblems` (`ProblemCacheSave`), затем ошибки лога и `sessionAnswer`. `systemMessage` — о конфиге, о метке активации, ведущей наружу (`ProblemActivationRefused`), или о том, что хук не может работать (`failNotice` — с фиксированной категорией причины, `SessionFailure`).
- `PromptSubmit` — снимок `session.FromTree(Project.Stats())` (отслеживаемые файлы и `StatsView` дерева), сброс журнала и файла увиденных доков.
- `Stop` — читает снимок, журнал и увиденные доки, вызывает `turn.Evaluate` и рендерит итог (`Feedback`, `StopReason`).
- `PreToolUse` — `allow` для безопасных вызовов `auto-context`.
- `PermissionRequest` (Codex) — `behavior: allow` для тех же вызовов, только когда Codex сам собрался спросить разрешение; иначе без вывода.
- `SessionEnd` — удаляет снимок, журнал и файл увиденных доков сессии без открытия проекта. В Codex не срабатывает при выходе из TUI; уборка старых файлов сессии держится на SessionStart (`session.RemoveStale`).
- `Stop`, `PromptSubmit`, `SessionEnd` при пустом (или из одних пробелов) `session_id` (`session.ValidID`) пишут строку в лог и ничего не делают: иначе такие сессии делили бы одни файлы `_`.
- `CheckEvent(event, in)` — ошибка (фиксированный текст), если `Input.HookEventName` непуст и не совпадает с событием подкоманды (`session-start` → `SessionStart`, `prompt-submit` → `UserPromptSubmit`, `stop` → `Stop`, `pre-tool-use` → `PreToolUse`, `session-end` → `SessionEnd`, `permission-request` → `PermissionRequest`); пустое имя проходит. Вызывает и решает реакцию `cmd/auto-context`.

## Агент
`Env.Agent` (`Claude`, нулевое значение; `Codex`; `ParseAgent` для `--agent`) решает, как тексты называют навыки и команды: `Agent.Skill(name)` — `auto-context:<name>` или `$auto-context:<name>`, `Agent.Command(name)` — `/auto-context:<name>` или `$auto-context:<name>`. Имя индексного файла берётся из `Project.IndexFile()`. Stop у Codex отвечает `{"decision":"block","reason":…}` (только так Codex продолжает ход), у Claude — `additionalContext`. `Input.ToolInput` — сырой JSON; `Input.Command()` возвращает строку только под точным ключом `command`; другая форма `tool_input` — "" без ошибки, а ключ, равный `command` без учёта регистра (`Command`), делает команду неизвестной: `encoding/json` сопоставляет поля без учёта регистра, и хук мог бы судить не ту команду, что запустит агент.

## Устройство Stop
Правила хода живут в чистом пакете `internal/turn` (подробно — `context/internal/turn.md`): что считается обновлением доков, когда допустим auto-ack, какие юниты в pending, новые и исчезнувшие юниты, «Unit list changed», пометки в журнале. `Stop` — ввод-вывод вокруг одного вызова `turn.Evaluate` (в `stop.go` пакет импортирован как `rules`: `turn` — имя тестового хелпера пакета).
1. Ввод: снимок начала хода (`session.LoadSnapshot`), текущий снимок `session.FromTree(p.Stats())`, журнал (`loadJournal(root, id, hook)`: нечитаемый — в лог и пустой), увиденные доки (`loadSeenDocs`), время снимка (`session.SnapshotTime`; сбой — 0). Сам `*project.Project` — `turn.View` дерева (узкие методы `Units`, `IsUnit`, `UnitOf`, `Files`, `Classifier`). Время удаления файла даёт `repoDirStat` (`os.Lstat`, только настоящий каталог; сам корень — через `os.Stat`, репозиторий может быть открыт по ссылке), исчезновение с диска — `repoGone`.
2. Эффекты, которые `Evaluate` вызывает по порядку: `Recorded` — запись журнала после учёта diff (и строка в лог, если бюджет хука кончился: «only part of this turn's changes was recorded»); `Ack` — `autoAck` (`Project.AckTouched`, ошибки в лог, причина — `errCategory`), затем `saveSeenDocs`: stat подтверждавшихся доков (как его берёт `Discover`: у ссылки — цель) в `.auto-context/state/<session>.docs` (`seenDocsPath`, P-M2); `Prewarm` — параллельное хеширование файлов юнитов с изменённым кодом (`Project.Prewarm`), после чего `UpToDate` (`Project.UpToDate`) берёт хеши из кэша. Без кандидатов `AckTouched` не вызывается (тесты считают вызовы через `ackTouched`).
3. Вывод: `SaveCache`; при `Outcome.Quiet()` — молчание (снимок и журнал остаются). Иначе `buildFeedback` делит pending по виду дока (`docstate.Doc`): код без доков, новые юниты (Claude сначала спрашивает пользователя), context-файл со ссылкой наружу, нечитаемый context-файл, неудачный ack; плюс «Unit list changed» и доки исчезнувших юнитов (`Outcome.ListChanged`, `Outcome.Removed`). Затем сохраняется `Outcome.Journal` — с пометками о сказанном. В каждом сообщении не больше 20 юнитов, остальные числом. Имя-аргумент команды (`cmdArg`): с пробелом — в кавычках, с ведущим `-` — как `./name` (на случай ослабления `SafeName`). Доки исчезнувших юнитов названы только по именам, прошедшим `units.SafeName`.

## Инварианты и подводные камни
- Активация — `project.Active`; в неактивном проекте хуки ничего не пишут. `PreToolUse` ничего не пишет и работает в любом проекте.
- Конфиг, который не читается или не разбирается (`ConfigBroken`): Stop один раз за период поломки говорит «tracking is paused» (`Journal.ConfigNotified`; текст — `ProblemConfigUnreadable` канала `project.Stop`), PromptSubmit не трогает снимок и помечает журнал `Paused`. Когда конфиг исправлен — в ходе или между ходами, — снимок остаётся прежним, а `Journal.Resume` сбрасывает пометки и старые напоминания: Stop видит все правки этого периода. Если снимка нет, а журнал на паузе, Stop снимает паузу без записи в лог. Нечитаемый журнал PromptSubmit и Stop логируют и начинают с пустого. Снимок PromptSubmit разбирает, только когда может его сохранить (пауза или нечитаемый журнал); нечитаемый снимок он логирует и заменяет. SessionStart в это время сообщает только о конфиге и об ошибках лога.
- Правила auto-ack (старый mtime, время удаления по каталогу, увиденные доки, неудачный ack не повторяется, пока док не изменится — `TestStopFailedAckNotRetriedUntilDocChanges`) — в `context/internal/turn.md`.
- Чистый Stop не удаляет снимок: другой Stop-хук может продолжить ход.
- Напоминание — не чаще раза на юнит за ход (`AlreadyNotified`, его ставит `turn.Evaluate`, сброс в PromptSubmit).
- `stop_hook_active` игнорируется намеренно; от зацикливания защищает `AlreadyNotified`.
- Без снимка Stop сохраняет новый и молчит; в лог пишет «this turn's changes are not tracked», только если state-dir уже был (иначе проект включили в этом ходе). Нечитаемый или повреждённый снимок заменяется с записью в лог. Сбой первой записи журнала логируется; если не записался журнал с отметкой о напоминании, Stop молчит: иначе то же напоминание продолжало бы ход на каждом Stop.
- Правки индексного файла, включая собственные перезаписи индекса, обновлением доков не считаются (правило `turn`).
- SessionStart считает ошибки лога до своих записей и ставит отметку после (по часам ОС, как и время в логе): о своих проблемах он сообщает сам, а не как об ошибках хуков. Текст лога Claude не читает: лог может прийти из репозитория.
- Текст конфига и логов в контекст Claude не попадает — только числа и фиксированные категории; исключение — `language`, проверенный код языка (`LanguageNote`). Причина неудачного авто-ack или отказа SessionStart — фиксированная категория (`errCategory` — обёртка над `project.CauseOf(err).Text(project.Stop)`, единой таблицей причин; для `units.ErrGitTimeout`/`ErrListTooLarge` — совет про `.gitignore`, для `units.ErrTimeUp` — «the hook's time ran out; the repository may be too large or slow», для `project.ErrConfigBroken`/`ErrConfigDegraded` — «исправьте конфиг»), полный текст ошибки — только в логе. Путь CLI передаётся в `fmt.Sprintf` аргументом, не вклеивается в формат: `%` в корне плагина не портит текст.
- При заданном `language` SessionStart выводит `LanguageNote` всегда, даже когда доки актуальны. Stop добавляет его к напоминаниям о коде и новых юнитах.
- `PreToolUse` и `PermissionRequest` делят `approvable`: точное совпадение `^auto-context (ack|status|units|version|changes)( [A-Za-z0-9_./-]+)*$`, без trim, без `..` и без любого слова, содержащего `--exclude` (`ack --exclude` правит коммитный конфиг и идёт через обычный запрос разрешения); свойство проверяет `FuzzAllowedCommand`. Для Claude не одобряет, если в PATH есть пустой или относительный элемент (где бы он ни стоял: shell разрешает его от своего cwd, а не от cwd хука) или `auto-context` в PATH — не бинарь плагина (`shadowed(env.pluginRoot())`: `Env.PluginRoot`, иначе `CLAUDE_PLUGIN_ROOT`). Без корня плагина или вне PATH сравнение с бинарём плагина не работает. На Windows `LookPath` не видит шим без расширения, поэтому одобрение блокирует только затеняющий `.bat`/`.exe` в другом каталоге PATH.
- `Env.CLI()` — как тексты называют бинарь: у Claude `auto-context`; у Codex (в его shell `bin/` плагина не в PATH) абсолютный `<корень>/bin/auto-context`, корень — `Env.PluginRoot`, иначе `PLUGIN_ROOT` (его ставит Codex), иначе `CLAUDE_PLUGIN_ROOT` (`Env.pluginRoot`; чистая `codexCLI(root)`; при символах вне `A-Za-z0-9_./-` путь целиком в одинарных кавычках, `'` как `'\''`), а при пустой переменной, неабсолютном пути, невалидном UTF-8 или управляющих символах — `auto-context`. Путь склеивается через `/` (`path.Join`) на любой ОС: это текст для POSIX-shell, а не путь для файловой системы. Все предлагаемые команды (`StopReason` через `Feedback.CLI`, `configPaused`, SessionStart, `SessionFailure`) собираются через неё; `Agent.CLI()` удалён. `approvable` для Codex принимает только эту форму (литеральный префикс `env.CLI()+" "`, в том числе в кавычках; остальные правила те же), без проверки `shadowed`; голое `auto-context` для Codex не одобряется никогда (в его shell `bin/` плагина не в PATH), а при `env.CLI()` = `auto-context` не одобряется ничего.

## Тесты
- Тесты активации (`TestActive`, `TestSessionStartRefusedMarker`) создают ссылки через `testutil.Symlink` и не пропускаются молча; маркер-каталог `context/_root.md` тоже проверяется.
- Табличные тесты правил хода (`TestPendingUnits`, `TestRecordTurn*`, `TestTurnNew`) — в `internal/turn`; здесь — сквозные тесты Stop, golden-файлы, `TestBuildFeedback`, `TestRepoDirStatLinkedRoot`.
- `concurrent_test.go`: `TestConcurrentStopHooks` запускает несколько процессов теста (`TestHelperStop`, helper-process) с разными `session_id`, все правят и подтверждают одни доки; после — доки разбираются и актуальны, `cache.v5.bin` начинается с заголовка `acache 5`, одна пара маркеров в корневом индексе, нет временных файлов. `BenchmarkStopNoChange` — Stop без изменений на 200 юнитах.
