# internal/hooks
Обработчики хуков Claude Code и Codex: жизненный цикл хода, обратная связь о доках.

## Назначение
Превращает JSON-событие Claude Code или Codex в необязательный JSON-ответ: напоминает обновить `context/<unit>.md` после правок кода и сообщает пользователю о проблемах, которые он должен исправить сам.

## Публичный API / точки входа
Сигнатура `func(Env, Input) ([]byte, error)`; `nil, nil` — ничего не выводить. Все ответы — один тип `hookOutput` (поля с `omitempty`, `hookSpecificOutput` — указатель `hookSpecific`): каждый хук пишет только свои ключи, JSON прежний байт в байт (golden-файлы в `testdata/`).
- `SessionStart` — оркестрация шагов, каждый возвращает тексты проблем: `configProblem` (конфиг не читается или с отброшенными настройками), `envProblems` (конфиг под `.gitignore` или сбой этой проверки, непригодный кэш, предупреждения обхода в лог, уборка старых файлов сессий), чистая `classifyStatuses` (stale/missing/непригодные доки/число доков в старой схеме хэша — `statusGroups`), `unitProblems` (непригодные доки; «`<N> unit(s) were acked by an older auto-context; run `<cli> ack --upgrade`.`»; сироты — не больше 20 имён, прошедших `units.SafeName`, остальные числом (`project.ShowNames`); число предупреждений обхода), `indexProblems` (ошибки индекса; `project.ErrConfigDegraded` — фиксированный текст «индекс и auto-ack на паузе», без записи в лог), `cacheSaveProblems`, затем ошибки лога и `sessionAnswer`. `systemMessage` — о конфиге, о метке активации, ведущей наружу, или о том, что хук не может работать (`failNotice` — с фиксированной категорией причины, `SessionFailure`).
- `PromptSubmit` — снимок из `Tree.Stats()`, сброс журнала и файла увиденных доков.
- `Stop` — diff со снимком, журнал, авто-ack, обратная связь (`Feedback`, `StopReason`).
- `PreToolUse` — `allow` для безопасных вызовов `auto-context`.
- `PermissionRequest` (Codex) — `behavior: allow` для тех же вызовов, только когда Codex сам собрался спросить разрешение; иначе без вывода.
- `SessionEnd` — удаляет снимок, журнал и файл увиденных доков сессии без открытия проекта. В Codex не срабатывает при выходе из TUI; уборка старых файлов сессии держится на SessionStart (`session.RemoveStale`).
- `Stop`, `PromptSubmit`, `SessionEnd` при пустом (или из одних пробелов) `session_id` (`session.ValidID`) пишут строку в лог и ничего не делают: иначе такие сессии делили бы одни файлы `_`.
- `CheckEvent(event, in)` — ошибка (фиксированный текст), если `Input.HookEventName` непуст и не совпадает с событием подкоманды (`session-start` → `SessionStart`, `prompt-submit` → `UserPromptSubmit`, `stop` → `Stop`, `pre-tool-use` → `PreToolUse`, `session-end` → `SessionEnd`, `permission-request` → `PermissionRequest`); пустое имя проходит. Вызывает и решает реакцию `cmd/auto-context`.

## Агент
`Env.Agent` (`Claude`, нулевое значение; `Codex`; `ParseAgent` для `--agent`) решает, как тексты называют навыки и команды: `Agent.Skill(name)` — `auto-context:<name>` или `$auto-context:<name>`, `Agent.Command(name)` — `/auto-context:<name>` или `$auto-context:<name>`. Имя индексного файла берётся из `Project.IndexFile()`. Stop у Codex отвечает `{"decision":"block","reason":…}` (только так Codex продолжает ход), у Claude — `additionalContext`. `Input.ToolInput` — сырой JSON; `Input.Command()` возвращает строку только под точным ключом `command`; другая форма `tool_input` — "" без ошибки, а ключ, равный `command` без учёта регистра (`Command`), делает команду неизвестной: `encoding/json` сопоставляет поля без учёта регистра, и хук мог бы судить не ту команду, что запустит агент.

## Устройство Stop
`Stop` — ввод-вывод вокруг чистых шагов `recordTurn` → авто-ack (`Project.AckTouched`) → `pendingUnits` → `buildFeedback`.
1. Юниты с изменённым кодом копятся в журнале (`CodeChanged`), доки — только пути `context/<unit>.md` (`DocsTouched`); самый поздний mtime кода юнита Stop заново считает по diff со снимком начала хода. Журнал грузит общий `loadJournal(root, id, hook)`: нечитаемый — в лог и пустой. У удалённого файла mtime нет: время удаления — mtime ближайшего уцелевшего каталога (`repoDirStat`, `os.Lstat`, только настоящий каталог, не выше корня; сам корень — через `os.Stat`, репозиторий может быть открыт по ссылке; кэш на один Stop — `deletionTimes`).
2. Авто-ack — для доков из diff этого Stop, не старше последней правки кода юнита и изменившихся после прошлого Stop хода: после auto-ack Stop пишет stat этих доков (как его берёт `Discover`: у ссылки — цель) в `.auto-context/state/<session>.docs` (`seenDocsPath`), и док с тем же stat следующий Stop не подтверждает заново — иначе каждый Stop до конца хода перестраивал бы корневой индекс (P-M2). Неудачный auto-ack тоже не повторяется на следующих Stop хода, пока док не изменится: о сбое сказано один раз, с командой `<cli> ack <unit>`, которую нужно выполнить после устранения причины (`TestStopFailedAckNotRetriedUntilDocChanges`). Без кандидатов `AckTouched` не вызывается (тесты считают вызовы через `ackTouched`).
3. Перед этим изменённые файлы хешируются параллельно (`Project.Prewarm`). В pending не попадают подтверждённые, уже напомненные, переставшие быть юнитами и юниты, чьи доки и так совпадают с кодом (`UpToDate`); юнит с неудачным ack попадает, даже если доки совпадают; а если о его коде уже напоминали — пока о сбое не сообщено в этом ходе (`Journal.AckFailNotified`).
4. Набор юнитов в ходе (`listChangedParents`). Новизна — только по снимку начала хода (`turnNew`): юнит новый, если по снимку он не мог быть юнитом ни по одному правилу, по какому бы правилу он ни был юнитом сейчас: в снимке не было его маркера, прямо в каталоге было меньше `min_files` исходников (`directSources`: все исходники снимка в каталоге, включая удалённые с тех пор; без context-доков и индексных файлов), а у юнита по `include` — ни одного файла; в том числе авто-ackнутый. Юнит с `context/<u>.md` в снимке и `_root` не новые. Юнит без доков, существовавший до хода, не новый, что бы в него ни добавили или ни убрали (новый файл, добавленный или удалённый маркер): `_root` не поднимается (HS-4). Исчезнувший юнит (`recordTurn` → `removed`): `context/<u>.md` в снимке есть, `IsUnit(u)` ложно и файл под `u/` удалён с диска в этом ходе (`Lstat`; исключение через конфиг и переставшие отслеживаться файлы — не удаление). Родитель и `_root` нового юнита и исчезнувшего юнита, чей док остался, получают строку «`Unit list changed under <parent>: check context/<parent>.md.`», если их ещё нет в pending, о них не напоминали и их не подтвердили; хэш тут не проверяется — текст дока может перечислять юниты. Такие доки исчезнувших юнитов (только имена, прошедшие `units.SafeName`) названы в том же ходе — «`docs of units removed this turn: …`», со ссылкой на правило «Unit removed». Если док исчезнувшего юнита тоже удалён, сам юнит не называется, а родитель и `_root` получают «Unit list changed» только пока их доки не актуальны (`UpToDate`; хэш `_root` включает список юнитов, так что `_root` обычно назван, а родитель с неизменными файлами — нет); обновлённые и подтверждённые доки родителя и `_root` — молчание; всё это попадает в `AlreadyNotified`, поэтому один раз за ход.
5. Pending делится на: код без доков, новые юниты (Claude сначала спрашивает пользователя), context-файл со ссылкой наружу, нечитаемый context-файл, неудачный ack; плюс «Unit list changed» и доки исчезнувших юнитов. В каждом сообщении не больше 20 юнитов, остальные числом. Имя-аргумент команды (`cmdArg`): с пробелом — в кавычках, с ведущим `-` — как `./name` (на случай ослабления `SafeName`).

## Инварианты и подводные камни
- Активация — `project.Active`; в неактивном проекте хуки ничего не пишут. `PreToolUse` ничего не пишет и работает в любом проекте.
- Конфиг, который не читается или не разбирается (`ConfigBroken`): Stop один раз за период поломки говорит «tracking is paused» (`Journal.ConfigNotified`), PromptSubmit не трогает снимок и помечает журнал `Paused`. Когда конфиг исправлен — в ходе или между ходами, — снимок остаётся прежним, а `Journal.Resume` сбрасывает пометки и старые напоминания: Stop видит все правки этого периода. Если снимка нет, а журнал на паузе, Stop снимает паузу без записи в лог. Нечитаемый журнал PromptSubmit и Stop логируют и начинают с пустого. Снимок PromptSubmit разбирает, только когда может его сохранить (пауза или нечитаемый журнал); нечитаемый снимок он логирует и заменяет. SessionStart в это время сообщает только о конфиге и об ошибках лога.
- Auto-ack запрещён юниту, у которого изменённый файл кода старше начала хода (mtime меньше mtime снимка): порядок с правкой доков неизвестен. То же для удалённого файла, если mtime его ближайшего уцелевшего каталога старше начала хода или `Lstat` не удался. Удаление после правки доков auto-ack запрещает: удаление записи обновляет mtime каталога. Поздние посторонние правки в том же каталоге только завышают время удаления — это отказ от auto-ack и обычное напоминание, а не устаревшие доки, записанные актуальными.
- Чистый Stop не удаляет снимок: другой Stop-хук может продолжить ход.
- Напоминание — не чаще раза на юнит за ход (`AlreadyNotified`, сброс в PromptSubmit).
- `stop_hook_active` игнорируется намеренно; от зацикливания защищает `AlreadyNotified`.
- Без снимка Stop сохраняет новый и молчит; в лог пишет «this turn's changes are not tracked», только если state-dir уже был (иначе проект включили в этом ходе). Нечитаемый или повреждённый снимок заменяется с записью в лог. Сбой первой записи журнала логируется; если не записался журнал с отметкой о напоминании, Stop молчит: иначе то же напоминание продолжало бы ход на каждом Stop.
- Правки индексного файла, включая собственные перезаписи индекса, обновлением доков не считаются.
- SessionStart считает ошибки лога до своих записей и ставит отметку после (по часам ОС, как и время в логе): о своих проблемах он сообщает сам, а не как об ошибках хуков. Текст лога Claude не читает: лог может прийти из репозитория.
- Текст конфига и логов в контекст Claude не попадает — только числа и фиксированные категории; исключение — `language`, проверенный код языка (`LanguageNote`). Причина неудачного авто-ack или отказа SessionStart — фиксированная категория (`errCategory`; для `units.ErrGitTimeout`/`ErrListTooLarge` — совет про `.gitignore`, для `project.ErrConfigBroken`/`ErrConfigDegraded` — «исправьте конфиг»), полный текст ошибки — только в логе. Путь CLI передаётся в `fmt.Sprintf` аргументом, не вклеивается в формат: `%` в корне плагина не портит текст.
- При заданном `language` SessionStart выводит `LanguageNote` всегда, даже когда доки актуальны. Stop добавляет его к напоминаниям о коде и новых юнитах.
- `PreToolUse` и `PermissionRequest` делят `approvable`: точное совпадение `^auto-context (ack|status|units|version|changes)( [A-Za-z0-9_./-]+)*$`, без trim, без `..` и без любого слова, содержащего `--exclude` (`ack --exclude` правит коммитный конфиг и идёт через обычный запрос разрешения); свойство проверяет `FuzzAllowedCommand`. Для Claude не одобряет, если в PATH есть пустой или относительный элемент (где бы он ни стоял: shell разрешает его от своего cwd, а не от cwd хука) или `auto-context` в PATH — не бинарь плагина (`shadowed(env.pluginRoot())`: `Env.PluginRoot`, иначе `CLAUDE_PLUGIN_ROOT`). Без корня плагина или вне PATH сравнение с бинарём плагина не работает. На Windows `LookPath` не видит шим без расширения, поэтому одобрение блокирует только затеняющий `.bat`/`.exe` в другом каталоге PATH.
- `Env.CLI()` — как тексты называют бинарь: у Claude `auto-context`; у Codex (в его shell `bin/` плагина не в PATH) абсолютный `<корень>/bin/auto-context`, корень — `Env.PluginRoot`, иначе `PLUGIN_ROOT` (его ставит Codex), иначе `CLAUDE_PLUGIN_ROOT` (`Env.pluginRoot`; чистая `codexCLI(root)`; при символах вне `A-Za-z0-9_./-` путь целиком в одинарных кавычках, `'` как `'\''`), а при пустой переменной, неабсолютном пути, невалидном UTF-8 или управляющих символах — `auto-context`. Путь склеивается через `/` (`path.Join`) на любой ОС: это текст для POSIX-shell, а не путь для файловой системы. Все предлагаемые команды (`StopReason` через `Feedback.CLI`, `configPaused`, SessionStart, `SessionFailure`) собираются через неё; `Agent.CLI()` удалён. `approvable` для Codex принимает только эту форму (литеральный префикс `env.CLI()+" "`, в том числе в кавычках; остальные правила те же), без проверки `shadowed`; голое `auto-context` для Codex не одобряется никогда (в его shell `bin/` плагина не в PATH), а при `env.CLI()` = `auto-context` не одобряется ничего.

## Тесты
- Тесты активации (`TestActive`, `TestSessionStartRefusedMarker`) создают ссылки через `testutil.Symlink` и не пропускаются молча; маркер-каталог `context/_root.md` тоже проверяется.
- `concurrent_test.go`: `TestConcurrentStopHooks` запускает несколько процессов теста (`TestHelperStop`, helper-process) с разными `session_id`, все правят и подтверждают одни доки; после — доки разбираются и актуальны, `cache.json` — валидный JSON, одна пара маркеров в корневом индексе, нет временных файлов. `BenchmarkStopNoChange` — Stop без изменений на 200 юнитах.
