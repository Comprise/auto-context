# internal/project
Сервисный слой: открывает репозиторий и даёт хукам и CLI общие операции.

## Назначение
Хукам и CLI нужна одна последовательность «конфиг → обход → кэш → статусы → оглавление → кэш на диск» и одно правило, когда в проект можно писать; пакет держит их в одном месте.

## Публичный API / точки входа
- `FindRoot(cwd)` (`root.go`) — ближайший сверху каталог с `.git` или `config.FileName`, принадлежащими текущему пользователю (`ownedByUser`, `owner_unix.go`/`owner_other.go`); `$HOME` и каталоги сравниваются после `filepath.Clean` и `EvalSymlinks` (слеш в конце или симлинк в `HOME` не обходят защиту), возвращаемый путь — от исходного `cwd`. Раньше жил в `internal/config`.
- `Active(root)` — проект включён: `.auto-context/config.yaml` или `context/_root.md`, обычный файл внутри репозитория; `ActivationRefused(root)` — метка есть, но ведёт наружу, не обычный файл или недоступна. Оба — через общую `markerState(root)`.
- `Open(ctx, root)` → `*Project`, только для чтения (кроме кэша, загружаемого лениво, и `Exclude`, перечитывающего конфиг и дерево); его дерево неизменяемо — классификация путей (`Orphans` — `Tree.Classify` только для `context/*.md`, без правил `.gitignore`; Stop — через один `units.Classifier` на проход, `Project.Classifier()`) не тратит бюджет дерева и не добавляет предупреждений, `Warnings()` не зависит от числа классифицированных путей; `ctx` (бюджет хука или прерывание CLI) хранится в проекте и ограничивает все его вызовы git и хеширование: `Project` живёт один хук или одну команду; геттеры `Root()`, `IndexFile()` — имя индексного файла из конфига, `Config()`, `ConfigProblems()` — отброшенные настройки, `ConfigErr()` — конфиг не прочитан (`ConfigBroken()`).
- Узкие запросы к дереву вместо `*units.Tree` (A-M1): `Units()`, `IsUnit(dir)`, `UnitOf(rel)`, `Classify(rel)`, `Classifier()`, `Files(unit)`, `Stats()` — отслеживаемые файлы и общая карта stat (`StatsView`, только чтение) для `session.FromTree`, `WarningCount()`. `*Project` тем самым — `turn.View` для Stop. `Tree()` пока остаётся только ради `cmd/auto-context/changes.go` (вне файлов T28).
- `Cache()` — кэш отпечатков, загружается при первом обращении; `CacheErr()` — почему он непригоден. `ConfigIgnored()` — конфиг под `.gitignore`, ошибка — сбой git, кроме «не репозиторий» и «нет git»; `StateDirErr()` — `.auto-context` ведёт наружу.
- `Prewarm(files)` — параллельное хеширование изменённых файлов с периодическим сохранением кэша; при пустом списке кэш не загружается; `ShowNames(paths)` — пути, которые можно показать Claude (`units.SafeName`, не больше 20), и число остальных.
- Статусы, ack (`Ack` — через `docstate.AckIfNeeded`: док, где уже записан текущий хеш, не переписывается; пишет и HEAD в `commit`: один `git rev-parse --verify -q HEAD` на `Project`, лениво и только при перезаписи дока, в пределах `ctx` проекта; при сбое git или без коммитов `commit` не пишется, ack не падает; `AckTouched` — для авто-ack: оглавление обновляется при любом затронутом доке — summary мог измениться без смены хеша, — его ошибка возвращается отдельно; `Upgrade(now)` — ack юнитов, актуальных по старой схеме хеша (`NoteOldScheme`), возвращает подтверждённые и ошибки по юнитам), оглавление (`UpdateIndex` с полным списком статусов; `RefreshIndex` берёт summary из доков через `docstate.SummaryOf` и ничего не хеширует; в неактивном проекте оба ничего не читают и не пишут), `Exclude`, `SaveCache`, доки-сироты (`Orphans`), отчёт `changes` (`WriteChanges`).

## Инварианты и подводные камни
- При `ConfigBroken` `Ack`, `UpdateIndex`, `RefreshIndex` и `WriteChanges` отказывают (`ErrConfigBroken`): юниты по умолчанию не те. Если отброшена или сброшена настройка, решающая состав юнитов (`Config.DiscoveryReset`: include, exclude, track, min_files, code_extensions, module_markers), отказывают `Ack`, `AckTouched`, `Upgrade`, а также `UpdateIndex` и `RefreshIndex` (`ErrConfigDegraded`; `AckTouched` возвращает его как ошибку индекса): хеш и закоммиченное оглавление были бы по чужому набору юнитов.
- `Statuses` сначала параллельно хеширует изменившиеся файлы (`Cache.Prewarm`) и сохраняет кэш каждые 5 с: хук, убитый по таймауту, не теряет работу. Прогреваются только юниты, чей док записывает `source_hash` (v2 — индексный вид `HashFiles`, старая схема — `Files`): юнитам без дока или без ack хеш не нужен. Каждый док читается один раз (`docstate.ReadDoc`), статус строится по прочитанному (`docstate.StatusOfDoc`). Когда `ctx` кончился, `Statuses` возвращает частичный результат: нехешированные юниты — `NoteHashError` с `Detail` «the hook's time is up».
- `SaveCache` ничего не пишет в неактивном проекте, при `.auto-context`, ведущем наружу (ошибка `StateDirErr`), если кэш не загружался (PromptSubmit и большинство Stop) и если он не изменился, а `cache.json` уже есть (без O(файлов) `Prune`). Загруженный кэш всегда сначала проходит `fsutil.EnsureStateDir`, даже неизменённый: в проекте, включённом одним `context/_root.md`, и в проекте v1.0.0 с `cache.json` без `.auto-context/.gitignore` он появляется.
- `Exclude` принимает только существующий каталог, не `_root`; ошибка разрешения пути сообщается как есть. Каждый сегмент имени должен точно совпасть с записью `os.ReadDir` родителя (иначе `no directory X (names are case-sensitive)` при совпадении без учёта регистра, `no directory X in <root>` — без совпадения): на нечувствительной к регистру ФС неверный регистр прошёл бы `stat`, но шаблон бы не совпал. В конфиг пишется `config.EscapePattern(dir)` — `lib[v1]` исключается буквально. После записи конфиг и дерево перечитываются на месте (загруженный кэш остаётся и берёт stat нового дерева); при отказе конфиг не меняется.
- `Open` ничего не пишет; state-dir готовят `hooks.load` и `SaveCache`.
- `FindRoot` не поднимается в `$HOME` из подкаталогов (иначе `~/.auto-context/config.yaml` или dotfiles-`~/.git` делали бы корнем весь дом) и не доверяет меткам чужого владельца (общий `/tmp`); без меток возвращает cwd. Шим `bin/auto-context` держит свою копию алгоритма на sh без проверки владельца — расхождение намеренное и задокументировано.
- `WriteChanges`: сначала `gitx.WorkTreeOK`: если рабочее дерево или git-каталог лежат вне проекта (`core.worktree`, файл `.git` с `gitdir:` в чужой репозиторий) — `(git unavailable: the work tree or git dir lies outside the project; …)`, без git — `(git unavailable: …)`. Ошибки git выводятся только как `(git failed: <gitx.Brief>)` (`exit N`, `timed out`…): stderr git может цитировать значения локального конфига. Выбор диапазона — чистая `logSection` (аргументы через `slices.Concat`). Коммиты — `git log <commit>..HEAD`, если `commit` из frontmatter — полный hex-id в нижнем регистре (40 или 64 символа; иное из дока до git не доходит) и предок HEAD (`merge-base --is-ancestor`); иначе (поля нет, коммит ушёл после rebase — выход 1; неизвестный коммит, мелкий клон, тайм-аут — другой код, своя пометка) — `--since=<updated>` по дате коммита, и заголовок секции предупреждает, что позже влитые старые коммиты не видны. Пути относительно корня (`:(literal)<unit>`, `.` для `_root`, `--relative` у `log`/`diff`); без коммитов — только `git status` (новые и изменённые файлы); сбой `rev-parse HEAD`, кроме «HEAD нет», — заметка `(git failed: …)`; первая ошибка записи в `w` возвращается. Вывод git проходит через `textx.StripControls`: в темах коммитов могут быть escape-последовательности. Сравнение с рабочим деревом — только если все `filter.*` из глобального конфига или командной строки (`trustedFilters`, `--includes`, при ошибке — отказ), без захода в сабмодули.
