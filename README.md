# auto-context

Плагин Claude Code, который держит документацию проекта в актуальном состоянии и экономит токены.

- В каждом юните (каталог с модулем или с достаточным числом файлов кода) лежит короткий
  `CLAUDE.md` — назначение и ключевые файлы. Claude Code подгружает его только когда работает
  с файлами этого каталога.
- Подробное описание юнита живёт в `context/<unit>.md` и читается только при необходимости.
- В корневом `CLAUDE.md` поддерживается оглавление юнитов.

Когда Claude меняет код юнита, а документы остались прежними, в конце хода плагин напоминает
обновить их — или подтвердить, что правка несущественна (`auto-context ack`). Изменения,
сделанные между сессиями (`git pull`, ручные правки), показываются при старте сессии.
Если документация актуальна, плагин не добавляет в контекст ничего, кроме заданного языка доков
(`language`).

## Требования

- Claude Code (CLI, расширение IDE или desktop). claude.ai и Cowork плагин не поддерживают.
- Linux, macOS или Windows, amd64 или arm64.
- **Windows:** нужен [Git for Windows](https://git-scm.com/downloads/win). Без Git Bash Claude Code
  выполняет хуки через PowerShell, и плагин молча не работает. Если Git Bash установлен
  в нестандартное место, укажите путь в `settings.json`:

  ```json
  { "env": { "CLAUDE_CODE_GIT_BASH_PATH": "C:\\Program Files\\Git\\bin\\bash.exe" } }
  ```

  Если основной shell-инструмент Claude — PowerShell (`CLAUDE_CODE_USE_POWERSHELL_TOOL=1`),
  команды `auto-context` из навыков в нём не запустятся.

## Установка

```
/plugin marketplace add Comprise/auto-context
/plugin install auto-context@auto-context
```

Если у вас нет SSH-ключа для GitHub, задайте `CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1`.

### Обновление

Автообновление для сторонних маркетплейсов по умолчанию выключено. Обновить вручную:

```
claude plugin update auto-context@auto-context
```

или включите автообновление в `/plugin` → Marketplaces.

## Начало работы

Плагин ставится глобально, но работает только в проектах, где его включили. Признак — файл
`.auto-context/config.yaml` или `context/_root.md` в корне репозитория (сам по себе каталог `context/`
плагин не включает; метку-симлинк на файл вне репозитория — тоже, и при старте сессии сообщает
об этом). В остальных проектах плагин ничего не выводит и не создаёт никаких файлов; только
вызовы самого `auto-context` одобряются без запроса в любом проекте.

Корень проекта — ближайший сверху от каталога проекта Claude Code (`CLAUDE_PROJECT_DIR`; для
команд CLI — от текущего каталога) каталог с `.git` или `.auto-context/config.yaml`, а без них — сам этот
каталог. Поиск не поднимается в `$HOME` из его
подкаталогов и не доверяет меткам, принадлежащим другому пользователю.

Чтобы включить плагин в проекте, выполните в Claude Code:

```
/auto-context:init
```

Мастер найдёт юниты, покажет список на подтверждение и создаст документы.

## Команды

| Команда | Что делает |
|---|---|
| `/auto-context:init` | первичная разметка проекта: юниты и документы |
| `/auto-context:sync` | найти устаревшие документы и обновить их или подтвердить |
| `/auto-context:status` | краткая сводка состояния документации |

Claude вызывает CLI сам; вручную он тоже доступен:

| Команда | Что делает |
|---|---|
| `auto-context units` | список юнитов: путь, причина, число файлов |
| `auto-context status [--stale] [--exit-code]` | состояние документов: ok / stale / missing; с `--exit-code` — код 1, если есть stale/missing |
| `auto-context ack <unit…>` | правка несущественна — документы считаются актуальными; обновляет оглавление в корневом `CLAUDE.md` |
| `auto-context ack --exclude <unit>` | больше не считать каталог отдельным юнитом (каталог должен существовать) |
| `auto-context changes <unit>` | что изменилось в юните с последнего подтверждения доков: коммиты, незакоммиченные и новые файлы |

Одиночный простой вызов `auto-context ack|status|units|version|changes …` (без кавычек, пайпов,
`;` и т. п.) не требует подтверждения — плагин одобряет его сам, если `auto-context` из `PATH`
указывает на шим этого плагина. `ack --exclude` меняет `.auto-context/config.yaml` и поэтому всегда спрашивает
разрешение, в том числе внутри навыков плагина. Ваши правила `deny`/`ask` продолжают действовать.

## Настройка

Необязательный `.auto-context/config.yaml` (значения по умолчанию). Его стоит коммитить:
`.auto-context/.gitignore`, который ведёт плагин, исключает из git всё в этом каталоге, кроме
`config.yaml` и самого себя. Если ваш `.gitignore` скрывает `.auto-context/`, плагин предупредит —
уберите это правило.

```yaml
min_files: 5            # сколько файлов кода делает каталог юнитом
code_extensions: [.go, .ts, .tsx, .mts, .cts, .js, .jsx, .mjs, .cjs, .vue, .svelte, .py, .rs, .java, .kt,
                  .scala, .swift, .dart, .rb, .php, .cs, .fs, .c, .h, .cc, .cpp, .cxx, .hh, .hpp, .m, .mm,
                  .ex, .exs, .erl, .hs, .clj, .lua, .zig, .sh, .sql, .proto, .graphql, .tf]
module_markers: [go.mod, package.json, Cargo.toml, pyproject.toml, pom.xml, build.gradle]
include: []             # каталоги, которые всегда считаются юнитами
exclude: [vendor/**, node_modules/**, "**/testdata/**", dist/**, build/**]
track: []               # шаблоны файлов без кодового расширения, которые тоже считаются исходниками
                        # своего юнита (например, [".github/**", "bin/*", "hooks/*.json"])
max_session_notice: 10  # сколько юнитов перечислять в напоминании при старте
language: ""            # язык доков: код вроде ru, en, pt-BR; пусто — язык существующих доков
```

`language` — общий для команды язык `CLAUDE.md` юнитов и `context/`: плагин сообщает его Claude при
старте сессии и в напоминаниях, `/auto-context:init` спрашивает его. Принимается только код языка
(буквы, части через `-`), без свободного текста. Документ на другом языке Claude переводит, когда
обновляет его.

Заданный список (`code_extensions`, `module_markers`, `exclude`) заменяет значения по умолчанию,
а не дополняет их: если пишете свой `exclude`, перечислите и нужные из стандартных; ключ со
значением `null` оставляет значения по умолчанию. `auto-context ack --exclude` правит только ключ
`exclude` и сохраняет остальное содержимое файла. Исключённый так каталог перестаёт быть юнитом, а
его код учитывается в родительском; чтобы игнорировать каталог полностью, добавьте `<dir>/**`.

Ошибочная настройка (неизвестный ключ, `min_files: 0`, `max_session_notice` больше 100, расширение
без точки, некорректный шаблон, длиннее 256 байт или с больше чем 8 группами `{…}`) отбрасывается,
а остальные настройки продолжают действовать; при старте сессии плагин сообщает, сколько
настроек пропущено, а `auto-context status` показывает, какие именно. Только синтаксическая ошибка
YAML или нечитаемый файл (больше 1 МиБ, не обычный файл) отменяют весь файл; пока он не исправлен,
плагин не обновляет оглавление, не подтверждает доки и не советует удалять их.

### Как плагин видит файлы

Внутри git-репозитория (в том числе когда корень плагина — его подкаталог) список файлов берётся у
git (`git ls-files`), поэтому учитываются все `.gitignore`, `.git/info/exclude` и глобальные
исключения; игнорируемый маркер модуля юнита не создаёт. Вне git плагин обходит дерево сам и читает
`.gitignore` в каждом каталоге, включая правила `!`; слишком большой `.gitignore` (больше 256 КиБ,
5000 правил в файле, 10000 всего или 1000 правил, которые проверяются шаблоном, — с `/` или
сложнее `*.расширение`) пропускается с предупреждением. Если git есть, но не сработал, или корень
плагина игнорируется внешним репозиторием, плагин обходит дерево и сообщает об этом при старте
сессии. Таймаут git или репозиторий, где `git ls-files` выдаёт больше 256 МиБ путей (около 2 млн
файлов), — ошибка: плагин сообщит об этом вместо работы. Добавьте большие сгенерированные каталоги
в `.gitignore`: `exclude` тут не поможет, его плагин применяет уже к списку от git. Все вызовы git
одного хука укладываются в его таймаут; правила `.gitignore` с шаблонами при обходе без git тоже
ограничены по времени — сверх лимита они пропускаются с предупреждением.
Код внутри `context/` ни к какому юниту не относится: этот каталог отведён под доки, и плагин
предупреждает о таких файлах.

Исходники юнита — файлы с расширением из `code_extensions` (по умолчанию и `.sh`, `.sql`, `.proto`,
`.graphql`, `.tf`), из `track` и маркеры модуля (`go.mod`, `package.json`…): смена зависимостей тоже
делает доки устаревшими.

Отпечаток юнита (`source_hash`) не зависит от концов строк (CRLF и LF дают одно и то же), а у
`_root` включает и список юнитов: добавление или удаление юнита делает доки корня устаревшими.
Когда новая версия плагина меняет формулу отпечатка, затронутые юниты один раз показываются как
`stale`; если код не менялся, достаточно `auto-context ack <unit>`.

Симлинк на документ внутри репозитория работает, если он ведёт на другой `.md` (правка цели
считается правкой дока; например,
`CLAUDE.md -> AGENTS.md`: оглавление попадёт в `AGENTS.md`). Ссылки за пределы репозитория, в
`.git/` или на файлы другого типа (например, `.env`) плагин не читает и не пишет — это защита от
клонированных репозиториев, которые пытались бы через плагин изменить или утащить ваши файлы;
такой юнит в `auto-context status` помечен `stale (symlink outside repo)`. Каталоги с необычными
символами в имени (обратные кавычки, переводы строк и т. п.) юнитами не становятся.

Обновлением документов юнита считается правка `context/<unit>.md`, сделанная не раньше последней
правки кода этого юнита в том же ходе; правка одного `<unit>/CLAUDE.md` юнит актуальным не делает.
Если доки и так совпадают с кодом (правку откатили, переключили ветку, форматтер ничего не
изменил), плагин не напоминает. Доки юнита, которого больше нет, `auto-context status` и старт
сессии показывают как лишние; Claude удаляет их, только спросив вас.

Служебное состояние хранится в `.auto-context/` рядом с конфигом; плагин кладёт туда собственный
`.gitignore` (всё, кроме `config.yaml`, вне git) и ваш `.gitignore` не трогает. Файлы сессии удаляются при её завершении; оставшиеся после сбоя — через 7 дней.
`CLAUDE.md` юнитов и `context/` стоит коммитить.

## Если что-то не работает

- `/hooks` — должны быть видны хуки плагина `SessionStart`, `UserPromptSubmit`, `Stop`, `PreToolUse`, `SessionEnd`.
- `.auto-context/log` — ошибки плагина, включая падения бинаря. Сессию плагин никогда не ломает:
  хуки всегда завершаются с кодом 0. Старт сессии сообщает, сколько ошибок появилось с прошлой
  сессии, а `auto-context status` — сколько их всего (сам текст не выводит — лог мог прийти из
  репозитория). Если лог записать нельзя, ошибка уходит в stderr хука.
- Если хук не может работать (например, `.auto-context` ведёт за пределы репозитория) или бинарь
  для вашей платформы не найден, при старте сессии во включённом проекте плагин сообщит об этом.
- `claude --debug-file <path>` — лог вызовов хуков. Если в нём есть `Hook output does not start with {`,
  ваш shell-профиль что-то печатает в stdout и мешает хукам.

## Разработка

```sh
make test                         # тесты
make dist                         # бинарники для 6 платформ в libexec/
claude --plugin-dir /path/to/auto-context
```

Релиз: `git tag vX.Y.Z && git push origin vX.Y.Z` — по одному тегу, дождавшись окончания workflow
(из нескольких одновременно ожидающих запусков GitHub оставляет только последний). Тег должен быть
`vMAJOR.MINOR.PATCH[-pre]` и стоять на коммите из `main`. Workflow соберёт бинарники, строго
проверит дерево плагина (`claude plugin validate --strict`), обновит ветку `release` (только если
версия выше текущей; теги с `-` её не трогают) и опубликует GitHub Release. Версия берётся из тега.

Ветку `release` workflow только наращивает (без force-push), поэтому бинарники всех релизов остаются
в её истории, и клон плагина со временем растёт: 6 бинарников на релиз. Историю `main` она в себя не
включает: исходный коммит релиза указан в сообщении коммита.
